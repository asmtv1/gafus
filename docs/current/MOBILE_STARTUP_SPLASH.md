# Мобильный стартовый экран (iOS / Android)

Актуально: 29.10.2026.

## Визуальный контракт
- Единый локальный статический постер «Всё у тебя получится!»:
  `apps/mobile/assets/images/startup-splash.png` (1080×1920, RGB, оптимизированный PNG).
- GIF для запуска не используется, не префетчится и не декодируется.
- `apps/mobile/app.json` указывает этот PNG для нативного splash Expo/iOS, а `StartupLoader.tsx` отображает тот же PNG из локального bundle через `react-native/Image` с `resizeMode="cover"`.
- Нативный splash удерживается через `SplashScreen.preventAutoHideAsync()` до события `onLoadEnd` статического постера в JS. На запуск не влияет предварительная загрузка GIF/маскота.
- Оверлей снимается, когда загружены шрифты и завершена проверка авторизации. Пока каталог курсов находится в состоянии `isLoading`, начальная вкладка курсов показывает тот же `StartupLoader` вместо обычного индикатора. При ошибке API отображается предусмотренный экран ошибки (без бесконечного splash).
- На Android 12+ системное окно заставки ограничивается платформой (центрированная иконка); после инициализации JS показывается полноэкранный PNG. На iOS полноэкранный нативный постер задан в SplashScreen.storyboard.

## Проверка
- `pnpm --filter @gafus/mobile exec vitest run src/shared/components/StartupLoader.test.ts`
- `pnpm --filter @gafus/mobile typecheck`
- Проверить холодный старт на реальном устройстве: нативный splash → постер без GIF → загруженные курсы/ошибка, а также офлайн-сценарий и быстрый повторный запуск.
- Изменение **исходного изображения native splash** потребует повторной сборки мобильного приложения. Изменение JS-компонента в dev передаётся через Metro Reload; обычные OTA-обновления не подменяют нативные launch assets.

Production, App Store, Google Play, CI/CD и Main в рамках этой работы не менялись.
