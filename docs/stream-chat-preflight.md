# Stream Chat: проверка перед интеграцией

Дата: 2026-10-01. Первичные проверки ниже сохранены как история. Авторизованная development-интеграция теперь проверена; актуальная приёмка — `docs/cynologist-chat-acceptance.md`, выпуск — `docs/cynologist-chat-release.md`.

## Требования продукта

- Чат независим от консультаций. Один кинолог, один постоянный диалог на клиента.
- MONTHLY и THREE_MONTHS включают чат; консультации переходят только в THREE_MONTHS.
- После окончания подписки история и ответы доступны, отправка клиента запрещена. Продление сохраняет диалог.
- UI: «Ответ в течение суток» и рабочие дни 10:00–19:00 МСК. SLA, дедлайны и вычисление срока ответа исключены из окончательного плана пользователя. Напоминания — отдельная серия каждые пять календарных часов с переносом в окно пн–пт 09:00–21:00 МСК.

### Контроль отправки

Before Message Send webhook работает fail-open: HTTP ошибка или timeout не блокируют сообщение. Поэтому он не может быть единственным барьером подписки.

Кандидат для прототипа: клиентские роли Stream имеют доступ к чтению, но не к созданию сообщений; отправка проходит через GAFUS API с проверкой подписки и серверный SDK. Загрузки также требуют отдельной проверки прав. Альтернатива: роли с отправкой, синхронизируемые по подписке; требует проверки гонок и сбоев синхронизации.

Источники:
- https://getstream.io/chat/docs/node/before-message-send-webhook/
- https://getstream.io/chat/docs/node/chat-permission-policies/

### Стоимость

Публичная страница: Build 1000 MAU / 100 concurrent connections; Start $499/месяц при помесячной оплате или $399/месяц при годовой.
Maker: до 2000 MAU / 100 соединений; соответствие критериям GAFUS и одобрение не проверены.
MAU учитывает подключившихся к чату пользователей, включая чтение истории. Соединения учитываются по устройствам.
Для CDN и бесплатного плана указаны ограничения, не все численные квоты раскрыты. Не считать видео безлимитными. Общая таблица fair usage и таблица Build различаются; фактические квоты проверять в кабинете/у поддержки.

Источники:
- https://getstream.io/chat/pricing/
- https://getstream.io/maker-account/
- https://getstream.io/chat/docs/go-golang/fair-usage-limits/

### Push

Документация Stream предлагает Firebase/Notifee для React Native. GAFUS использует expo-notifications и RuStore dependency; точный существующий серверный mobile push маршрут ещё не прослежен. Не заменять текущую систему без проверки. Рассмотреть события Stream → существующая доставка GAFUS; проверить подпись, дубли и поведение на foreground/background/killed.

Источник: https://getstream.io/chat/docs/sdk/react-native/guides/push-notifications/

## Авторизованные SDK проверки

Запуск: изолированный каталог /tmp/gafus-stream-preflight, stream-chat 9.52.0, тестовый канал messaging:gafus-preflight-20261001. Ключи читались из исключённого из Git файла .env.stream-chat-test; значения не выводились. Три синтетических пользователя без персональных данных. Код GAFUS и его зависимости не изменены.

Подтверждено фактическими вызовами:
- Включены authentication и permission checks.
- Три пользовательских WebSocket-соединения успешно установлены из текущего сетевого выхода среды (не доказательство WebSocket из РФ).
- Клиентское сообщение получено через message.new другим участником.
- Прочтение отражено в read state, ответ второго участника сохранён.
- Третий пользователь не может прочитать приватный канал: 403 / code 17.
- Синтетический MP4 загружен и скачан (200, 3050 байт); PNG загружен и скачан (200).
- Ссылка на PNG без подписи отклонена: 403. Подписанная ссылка доступна без пользовательского токена — это bearer URL, не проверка членства при каждом скачивании.
- config_overrides.grants запретили create-message и upload-attachment: обе операции отклонены 403 / code 17 при уже открытом соединении. История продолжает читаться.
- Серверный SDK может отправить ответ от имени кинолога при клиентском запрете: подтверждено.
- Попытка снять запрет через unset config_overrides не восстановила отправку: 403. Явное возвращение разрешений восстановило отправку. В реализации использовать проверенный способ, не считать unset достаточным.
- После disconnect/connect история доступна. Это reconnect, а не испытание потери сети на устройстве.

CDN через российские Globalping probes (исправленное разделение path и query):
- Rostelecom, Kostroma: HTTP 200, 171 мс.
- Vimpelcom, Moscow: HTTP 200, 188 мс.
- ER-Telecom Holding, Tula: HTTP 200, 183 мс.

Осталось: native сборка и интерфейсы web/mobile, воспроизведение пользовательских форматов видео, push на реальных устройствах, WebSocket через российскую домашнюю/мобильную сеть, реальные права по подписке через GAFUS API, квоты вложений и способ оплаты. Подписка проверена только моделированием прав, не интеграцией с биллингом GAFUS. План интеграции ещё не завершён.

## UI-прототипы, 2026-10-01

Изолированный проект `/tmp/gafus-stream-prototype`, исходники сохранены в `output/stream-chat-prototype/source`. Web UI использует Stream React v14 и MessageComposer; Expo — Stream Chat Expo v9. Подключение через useCreateChatClient; выход размонтирует подключённый компонент. Вход выбирает только синтетическую роль на локальном сервере 127.0.0.1:4318, это не production авторизация. Секрет не передаётся клиенту.

Проверено через браузер: вход обеих ролей в отдельных вкладках, отправка вопроса клиентом, доставка кинологу, ответ кинолога и доставка клиенту, выход и повторный вход с сохранением обоих сообщений. Фото отображается, MP4 показывает длительность 2 секунды. Воспроизведение пользовательских MOV/HEVC не проверено. Веб-экспорт успешен, основной JS 4.23 MB (несжатый); это отдельный прототип, не оценка прироста bundle GAFUS.

Нативный статус будет дописан после сборки. Первую попытку Metro пришлось повторить: её запустили во время переустановки зависимостей, когда файлы SDK ещё заменялись. Этот сбой не является доказанным дефектом Stream.

Дополнительно: фото и MP4 загружены через файловый picker веб-интерфейса и отправлены с подписями. Доставка вложений в интерфейс кинолога подтверждена.
