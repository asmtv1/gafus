# GAFUS: дополнительная локальная приёмка iOS IAP + подписанного OTA, 13.11.2026

## Итог

**Локально выполнено.** Дополнительно к `gafus-ota-local-final-20261112.md` закрыта реальная нативная iOS simulator сборка/установка, применение новых OTA-миграций поверх исходной схемы, старый Prisma runtime против новой БД, ужесточение входа телеметрии, offline-first запись события перед reload, повторяемый нативный Podfile plugin и fingerprint с untracked native inputs. **Не является production-release или Apple Sandbox QA.** Работа выполнена в общем сильно изменённом локальном дереве с параллельными агентами, без `git reset`, `merge`, `commit`, `push` и без обращения к production.

## Проверки, закрытые за этот проход

1. **Xcode нативная сборка, а не только Expo export.**
   - `xcodebuild -workspace apps/mobile/ios/Gafus.xcworkspace -scheme Gafus -configuration Debug -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' -derivedDataPath /tmp/gafus-ota-simulator-derived-20261113 CODE_SIGNING_ALLOWED=NO build` → `** BUILD SUCCEEDED **`.
   - `simctl boot` iPhone 17 (iOS 26.2), `simctl install` приложения с bundle ID `ru.gafus.app` → успешно, установленное приложение найдено в Simulator container. После теста симулятор выключен.
   - Проверенный `unzip -tqq` архив: `/tmp/gafus-ota-ios-simulator-Gafus-20261113.zip`, около 123 МБ. Это **не IPA для App Store** и не подписанная production сборка. Xcode DerivedData (~12 ГиБ) удалён *после* архивации; свободно ~38–39 ГиБ. Исходники проекта и чужие сборки не удалялись.
   - **Не проверены:** запуск с Metro/API, StoreKit local transactions, физический Sandbox iPhone, дистрибуция/TestFlight.
2. **Реальные старые Prisma ORM-операции на новой схеме.** Из `git show HEAD:packages/prisma/schema.prisma` создан отдельный Prisma Client **6.10.1, 190 моделей** в временном каталоге без изменения текущего Prisma клиента. Им через транзакцию созданы и прочитаны `User`, `Course`, `Training`, `UserCourse`, `Chat2Conversation`, `Chat2OutboxEvent`; обновлена очередная запись, проверен join; транзакция принудительно отменена и записи не сохранились. PASS как на историческом `HEAD` snapshot + 7 OTA-миграций, так и на полном текущем QA schema snapshot. Повторяемый тест `scripts/verify-ota-legacy-prisma-compat.mjs --execute` генерирует и удаляет временный старый клиент автоматически. Это проверка старого **ORM**, не запуска старых процессов API и Worker.
3. **Миграции поверх старой схемы.** `scripts/verify-ota-migration-upgrade.mjs --execute`: создаёт случайную БД `gafus_ota_ephemeral_*` только на локальном PostgreSQL 127.0.0.1:55673, восстанавливает исходную модель `HEAD` в отдельную БД (`db push` только там), накатывает **семь** OTA SQL-миграций в правильном порядке, проверяет пять ключевых OTA-таблиц и `rolloutPercent` аудита, затем **удаляет только собственную временную БД**. PASS. Это безопасный способ проверять upgrade; не исправляет старую историю `prisma migrate deploy` на абсолютно пустой БД (историческая миграция `20241108120000_exam_result_trainer_review` по-прежнему зависит от существовавшей `ExamResult`). Схема при этом аддитивна: **190 исходных моделей, 200 текущих, 1926 проверенных старых физических колонок, 70 старых enum, 5 новых необязательных полей**.
4. **Телеметрия OTA не блокирует запуск обновления.** При `DOWNLOADED` сначала сохраняет событие в ограниченную локальную очередь без ожидания HTTP; `reloadAsync` может продолжаться. На следующем запуске очередь отправляется. Добавлен regression test offline flush. Серверный маршрут `/ota/telemetry` теперь читает **не более 4096 байт** даже при отсутствующем `Content-Length`/streaming, отдаёт 413 на превышение; не хранит сырые исключения, ID аккаунта или IP, только HMAC случайного installation UUID. Авторизованный сервером выпуск отдельно проверяется. События client-reported, а не доказанные платформой; 30-дневный retention остаётся явной админ-командой.
5. **Нативный iOS источник YooMoney удалён воспроизводимо.** Генерируемый `apps/mobile/ios/Podfile` игнорируется Git; его ручное изменение не было бы релизным исправлением. Поэтому новый config-plugin `apps/mobile/plugins/withIosStoreKitOnlyPodfile.js` зарегистрирован **последним** в `apps/mobile/app.json`. Он удаляет старый приватный `git.yoomoney.ru` CocoaPods source на каждом `prebuild` и отказывает, если в Podfile появится настоящий YooKassa native pod. Параллельно `apps/mobile/scripts/verify-ios-payment-native-deps.mjs` проверяет Podfile, Podfile.lock и Xcode project при наличии сгенерированного `ios`; в чистом CI checkout честно сообщает `CONFIG_PLUGIN_ONLY`, поскольку native files отсутствуют. Нативный CocoaPods SDK YooKassa в локальном Podfile.lock отсутствует. Дополнительные положительные/отрицательные тесты plugin/audit прошли. iOS paywall Apple IAP остаётся отделённым от Android/Web; source patch для обхода App Review не создан.
6. **Fingerprint включает незакоммиченные нативные входы.** `apps/mobile/scripts/native-source-fingerprint.mjs` теперь учитывает `git ls-files --others --exclude-standard` наряду с `--cached` для `apps/mobile/plugins`, app configs, modules и native файлов. Игнорируемый generated `ios/` не учитывается; изменения JS-only `apps/mobile/src/` по-прежнему не изменяют native fingerprint. Пять тестов PASS, включая новый незакоммиченный plugin, его изменение и удаление. На production это требует нового подтверждённого нативного дескриптора для действительно изменённой нативной композиции; никто не регистрировался и ничего не публиковалось.

## Что **локально не подтверждено** и почему

- **Полная старая история миграций с нуля**: P3018 на историческом pre-baseline шаге 2024, прежде чем создаётся `ExamResult`. Исправление истории — отдельная согласованная миграционная стратегия, а не переименование прошлых миграций поверх существующего production.
- **Полные старые процессы API/Worker на мигрированной БД с реальными данными**: проверен старый ORM и текущая типизация Worker, но не старые процессы на реальной копии данных; это нужно для финальной общей приёмки.
- **Настоящая Apple Sandbox транзакция/Restore и App Review**: локальный Xcode debug native и Hermes проверены, но тестовых StoreKit SKU/config в источниках нет, устройства не предоставлены и реального Apple статуса не подтверждали.
- **Cloud.ru S3/Beget CDN/AppTracer и protected GitHub environment**: локально прошли фальшивые endpoints/криптография, но для фактических проверок нужны отдельные preview секреты и реальные сервисы.
- **Подписанная нативная preview сборка с выбранными fingerprint/runtime/certificate и OTA на устройстве**: на симуляторе установлена только отладочная сборка; это не те же условия, что StoreKit Sandbox или staged OTA после дистрибуции.
- **Общая регрессия всех остальных модулей монорепо 33+5**: эта локальная работа закрыла собственные 20 OTA-этапов, но не заменила глобальную приёмку объединённой версии с параллельными изменениями других агентов.

**Безопасность:** Git HEAD остался прежним, изменений других агентов не откатывали, production/EAS/Apple не затрагивали, merge/push/commit не выполняли. Заключительные тесты могут быть повторены без изменения доверенных production объектов.
