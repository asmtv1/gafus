# GAFUS iOS / signed OTA: локальная реализация и приёмка 12 ноября 2026

**Статус:** локальная OTA-реализация, поэтапная выдача и псевдонимная аналитика реализованы и проверены. Физические устройства, реальные Cloud.ru/Beget/AppTracer, защищённый GitHub CI и магазинное ревью **не проверены**. Production/EAS не менялись; merge/push не выполнялись. Совместное дерево `gafus-refactor` содержит незакоммиченные изменения многих параллельных агентов; не считайте этот checkpoint релизным коммитом.

## Что реализовано

1. **iOS Apple IAP.** В iOS заменён новый сценарий checkout на Apple; StoreKit восстановление синхронизирует покупки, затем проверяет signed JWS на сервере; смена аккаунта останавливает продолжение восстановления. Проверены реальные Hermes JS bytes на отсутствие нового ЮKassa checkout. Android/Web не переписывались; отмена ранее активных ЮKassa-продлений — отдельная операция, не новый магазинный checkout.
2. **Приватная проверка source patch.** Реестр `MobilePatchDefinition`/`MobilePatchApplication`, UUID/idempotency, SHA-256, разрешённые базы/пути, sandbox `git apply --check` и фиксация результата. Это *не* скрытый OTA-возврат внешней оплаты. Существующий iOS-бинарник нельзя обновить таким патчем; любая новая оплата требует нового соответствующего правилам Apple нативного релиза и App Review. Фактический внешний checkout-патч не создавался.
3. **Подписанный OTA Protocol v1.** Экспорт Hermes + приватные source maps; проверка версии, runtime, native fingerprint, сертификата, источников; подпись RSA-SHA256 точных байтов манифеста; S3 immutable `If-None-Match:*`; S3 HEAD+GET и CDN GET с проверкой SHA256; REST CI callback; атомарные READY-артефакты, запрет повторного использования operationId с иной подписью/содержимым.
4. **Админка.** Регистрация и подтверждение/отзыв нативной поставки; создание paused deployment; публикация/пауза/аудит; привязка к native fingerprint; безопасный monoтонный rollout **1/10/50/100%** по детерминированным группам физических установок, кнопки в админке; просмотр клиентской статистики OTA. Снижение процента до меньшего блокируется; экстренная пауза возможна отдельно.
5. **Стабильные cohort keys.** `expo-secure-store` хранит случайный UUID установки, `expo-updates.setExtraParamAsync` отправляет его как `expo-extra-params`. Для новых self-hosted binary автозапрос Expo отключён до инициализации UUID; существующие EAS binary не затронуты. При частичной выдаче невыбранной группе возвращается старый подписанный READY update (если он есть), иначе 204. Подмена runtime/fingerprint/ключа не даёт получить релиз чужой группы.
6. **Статистика установки и ошибок.** `LAUNCHED`, `CHECKED`, `DOWNLOADED`, `UPDATE_ERROR`, `ROLLBACK_DETECTED`; ограниченная offline-очередь; HTTP rate limit, HMAC установки с отдельным серверным секретом, строгие enum-поля без текстов исключений и аккаунтов, не более 150 событий/сутки на установку, дедупликация `eventId`, агрегирование и 30-дневное удаление. Статистика явно помечена как **сообщённая устройствами**, без доказательства каждого запуска. `packages/mobile-ota-server/scripts/prune-telemetry.mjs --dry-run|--execute` требует approval на реальных БД; автоматический production job ещё не подключён.
7. **Контроль AppTracer.** Версия OTA для AppTracer соответствует конкретному update ID и хранится в signed Expo extra. Старый EAS fallback сохранён. Source maps не раздаются с публичными bundle assets.
8. **Preview workflow.** `.github/workflows/gafus-self-hosted-ota-preview.yml`: защищённое GitHub environment, точный Git SHA, pinned Node/pnpm, проверенный native descriptor, fingerprint, typecheck, JS-only export, подпись, S3/CDN readback, source maps и CI callback, который сохраняет `READY`, **но не публикует автоматически**. Secrets scoped to steps. Реальный запуск этого workflow требует настройки внешнего окружения.
9. **Архитектура.** Prisma/SQL принадлежат отдельному `@gafus/mobile-ota-server`; Hono-маршруты через фасады, Core → server boundary не нарушен. Аддитивные миграции собственных OTA-таблиц и метаданных.

## Локальная проверка

- Последовательный runner: **17/17 PASS**, `/tmp/gafus-ota-regression-final-20261112/manifest.json`; отдельные логи по каждому этапу.
- Проверки в runner: 69 тестов API, 118 Mobile/Apple/Tracer, 23 интеграционных теста на настоящем **изолированном** PostgreSQL, 31 offline/CI/crypto/source тест, 4 S3/CDN теста, 4 теста детерминированного rollout. Типизация API, Mobile, Admin, Worker, сборки API, Admin, OTA-server, архитектура — PASS.
- Полный синтетический end-to-end: Hermes bytecode → RSA подпись → fake Cloud.ru S3/Beget CDN (SHA256 readback) → настоящий PostgreSQL READY → paused deployment → 1% cohort → HTTP protocol signed response → расширение 100% → pause. **Не равен реальному Cloud.ru/Beget end-to-end**.
- Финальные Expo JS exports: iOS **7 073 900 байт, 116 ассетов**, Android **7 146 628 байт, 131 ассет**, отдельные source maps; JS-export проверен, нативные IPA/AAB не создавались.
- Совместимость БД: сравнение `HEAD:packages/prisma/schema.prisma` с расширенной схемой — **190 старых моделей, 200 текущих, ни одного удалённого/изменённого исходного поля**. На отдельной БД, развёрнутой из *текущей* Prisma schema, подтверждены **1926 исходных физических колонок**. TypeScript текущего Worker зелёный. Это **структурная**, не полноценная old-binary runtime проверка.
- Полная история миграций **не** разворачивается с пустой БД: историческая миграция `20241108120000_exam_result_trainer_review` требует ранее отсутствующую `ExamResult` (Prisma P3018). Для структурной проверки использовался `prisma db push` на отдельную QA БД. Не применять `db push` к production для обхода этого блокера.

## Внешние/релизные блокеры

1. Проверить на физических iOS и Android: StoreKit Sandbox, reinstall и восстановление Apple, реальные платёжные webhooks, OTA первая установка/фоновая работа/сбой загрузки/переключение Wi-Fi, rollback, AppTracer/нативные падения. Сейчас iOS-симуляторы доступны, но выключены, Android-устройств по `adb` нет; StoreKit `.storekit` конфигурация в проекте отсутствует.
2. Создать и проверить новый нативный preview IPA/AAB с self-hosted URL, подписанным сертификатом, native fingerprint и проверкой на устройстве. Существующие EAS/store-сборки не менять.
3. Отдельно настроить **protected `ota-preview` GitHub environment** и точные секреты/публичные переменные preview API, Chat2, AppTracer, Cloud.ru S3/Beget CDN; запустить настоящие workflow и S3/CDN readbacks; проверить 307 fallback и кэши. Не хранить приватный RSA-ключ в репозитории.
4. Запустить совместимый старый API и Worker на полном тестовом снимке реальных данных, восстановить полноценную baseline историю миграций и выполнить общую 33+5/полную регрессию после завершения параллельных изменений других агентов. Выполненные адресные тесты этого не заменяют.
5. Отдельно принять и назначить безопасный production retention job для 30-дневной очистки клиентской OTA-телеметрии. Не делать автоматическую паузу только по неаутентифицированным client-reported событиям — ими можно манипулировать.
6. Для source-only recovery сначала зафиксировать **новую clean Git базу** и согласованный с правилами магазина исходный патч. Возврат внешней iOS-оплаты через OTA после App Review не является допустимым путём; подготовленный framework ничего такого не публикует.

## Безопасное повторение

`node scripts/gafus-ota-local-regression.mjs` — dry-run списка этапов, без выполнения.

Для исполнения: установить `DATABASE_URL` и `GAFUS_OTA_TEST_PG_URL` **строго** на `postgresql://asmtv1@127.0.0.1:55673/gafus_ota_preview_qa?schema=public`, `GAFUS_OTA_TEST_ISOLATED=1`, а для физической сверки старых колонок `GAFUS_OTA_COMPAT_DB_URL=postgresql://asmtv1@127.0.0.1:55673/gafus_ota_snapshot_20261112?schema=public`; затем `node scripts/gafus-ota-local-regression.mjs --execute --with-isolated-db`. Скрипт не выполняет миграции, deploy, push или signing production; каждый этап пишет лог и останавливает дальнейшие при первом сбое.
