## Локальные результаты

- `pnpm test:system:contract` — 12 тестов, PASS.
- `pnpm test:unit --scenario training.complete` — PASS именованного unit-теста.
- `pnpm test:integration --scenario training.complete` — PASS трёх тестов изолированного PostgreSQL.
- `pnpm test:integration --scenario payment.lifecycle` — PASS 13/13 именованных случаев платежей и Apple/ЮKassa.
- `pnpm test:integration --scenario mobile.ota` — PASS 34 случаев (из них 27 обязательных в каталоге); это серверная интеграция, **не установка OTA на телефоне**.
- `pnpm test:integration --scenario chat.delivery` — PASS 3/3; `pnpm test:unit --scenario chat.delivery` — PASS.
- `pnpm test:integration --scenario feed.order` — PASS 4/4.
- `pnpm --filter @gafus/core test:coverage` — код 0. Из `coverage-final.json`: 6 653/9 546 операторов (69,69%), 5 085/8 132 ветвей (62,53%). Это файлы конкретного запуска, не весь монорепозиторий.
- Первоначальный запуск Compose — код 2 при недоступном Docker; после запуска Docker Desktop два стека `qa-compose-check-20261119` и `qa-compose-check-second-20261119` прошли проверки PG/Redis и были удалены без остаточных контейнеров.

## До ввода обязательных gates

- `vitest@4.1.0` и `@vitest/coverage-v8@4.0.18` не совпадают по точной версии — необходима синхронизация lockfile и повторный baseline.
- Legacy `describe.skip` нельзя считать доказательством интеграции. Именованные обязательные проверки отклоняют skip.
- В PG18-пилоте используется `db push`; миграции с данными — отдельный незавершённый сценарий.
- Проверки Playwright на чистом стенде, Android/iOS E2E и провайдерские тесты пока не пройдены.
