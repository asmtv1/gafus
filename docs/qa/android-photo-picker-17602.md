# GAFUS 1.7.6 · Android Photo Picker

## Аудит точек входа

| Точка входа | До миграции | Сценарий Android 17602 |
| --- | --- | --- |
| Фотоальбомы профиля и питомцев, повтор загрузки | `expo-image-picker`, запрос доступа к медиатеке | Системный выбор нескольких фото в пределах свободных мест. При повторе используется сохранённый источник либо выбирается одно фото. |
| Публикация, редактирование и комментарии «Моментов» | `expo-image-picker`, запрос доступа к медиатеке | Смешанный выбор фото и видео. Действуют лимиты редактора, существующая подготовка WebP и видео, прогресс и повторная отправка. |
| Фото варианта опроса в «Моментах» | `expo-image-picker`, запрос доступа к медиатеке | Системный выбор одного изображения. |
| Вложения в Chat 2.0 | Прямой вызов `expo-image-picker` для медиа и `expo-document-picker` для PDF | Системный выбор нескольких фото или одного видео. PDF по-прежнему выбирается через системный выбор документов. |
| Аватар новой группы Chat 2.0 | Прямой вызов `expo-image-picker` | Системный выбор одного изображения. |
| Замена аватара группы Chat 2.0 | Прямой вызов `expo-image-picker` | Системный выбор одного изображения. |
| Аватар профиля | `expo-image-picker`, запрос доступа к медиатеке | Системный выбор одного фото с квадратным кадрированием. |
| Основное фото питомца | `expo-image-picker`, запрос доступа к медиатеке | Системный выбор одного фото с кадрированием. |
| Фото документа питомца | `expo-image-picker`, запрос доступа к медиатеке | Системный выбор одного изображения. |
| Новый вопрос и ответ | `QPhotoPicker` вызывает `expo-image-picker` после запроса доступа | Системный выбор до пяти фото в пределах оставшихся мест. |
| Ветеринарные записи | Кнопки добавления уже заблокированы в `PetVetVisits`. Существующие вложения читаются через API. | В форме нет вызова галереи. Просмотр существующих файлов остаётся на прежнем пути. |
| Видеоотчёт курса или экзамена | `CameraView.recordAsync`, камера и микрофон | Сохраняется запись камерой и существующая отправка. Выбор файла из медиатеки в этом сценарии отсутствует. |
| Фото и видео камерой в «Моментах» | `expo-image-picker.launchCameraAsync` и `expo-camera` для разрешения микрофона | Запрос камеры, а для видео также микрофона. Камера использует собственный путь. |

Во всех перечисленных сценариях выбора Android получает доступ к выбранным URI через системный интерфейс и передаёт копии из кэша Expo существующим загрузчикам. `expo-media-library` и операции записи в общую медиатеку в мобильном приложении отсутствуют. `expo-image-picker` добавлял `READ_EXTERNAL_STORAGE`, а `expo-screen-capture` добавлял `READ_MEDIA_IMAGES` для API 33. Приложение использует блокировку снимков экрана, которую `expo-screen-capture` реализует отдельно от подписки на события снимков.

Документы питомца скачиваются в кэш приложения. Экспорт ветеринарного документа на Android идёт через системный выбор папки (`StorageAccessFramework`). Оба пути работают с отдельным файлом или папкой, которую выбрал пользователь.

## Проверка кандидата

| Сценарий | Свидетельство для приёмки |
| --- | --- |
| Альбом | На Galaxy A53 выбрать 5–10 тестовых фото из нескольких альбомов. После загрузки перечитать альбом и сверить число фото. Повторить одну ошибку загрузки и проверить отсутствие дубля. |
| Google Photos и Samsung | Проверить локальные файлы и отдельно облачный файл, доступный только через Google Photos. Сравнить переключение альбомов и число действий со сборкой 17601. |
| «Моменты» и чат | Выбрать фото и видео, открыть фото и проиграть видео после загрузки. Для чата проверить появление отправленного сообщения. |
| Аватары, документы и вопросы | Выбрать файл, проверить кадрирование там, где оно предусмотрено, и подтвердить отображение сохранённого файла. |
| Ошибка, отмена и перезапуск | Закрыть системный экран без выбора, проверить пустой редактор. Затем повторно выбрать файл после перезапуска. Для недоступного облачного файла проверить сообщение и повтор. |
| Камера, авторизация, курсы, навигация и OTA | Записать тестовое видео с микрофоном, открыть курс и переходы из приложения, проверить старт и совместимость OTA с `runtimeVersion` 1.7.6. |

Для файлов и сообщений используйте тестовые данные. Сверяйте снятое на устройстве видео и облачный файл отдельно от результата тестов с подменённым провайдером.

## Артефакт Google Play

Из корня репозитория проверьте оба манифеста. `BUNDLETOOL_JAR` должен указывать на официальный `bundletool-all`.

```sh
node apps/mobile/scripts/verify-android-media-permissions.mjs "$MERGED_ANDROID_MANIFEST"
node apps/mobile/scripts/verify-android-media-permissions.mjs "$ANDROID_AAB"
java -jar "$BUNDLETOOL_JAR" validate --bundle="$ANDROID_AAB"
java -jar "$BUNDLETOOL_JAR" dump config --bundle="$ANDROID_AAB"
jarsigner -verify "$ANDROID_AAB"
node apps/mobile/scripts/verify-android-payment-aab.mjs "$ANDROID_AAB"
node apps/mobile/scripts/verify-android-aab-16k.mjs "$ANDROID_AAB"
node apps/mobile/scripts/verify-android-aab-compressor.mjs "$ANDROID_AAB"
node apps/mobile/scripts/verify-android-aab-app-links.mjs "$ANDROID_AAB"
```

В AAB ожидаются пакет `ru.gafus.app`, `versionName` 1.7.6, `versionCode` 17602, `PAGE_ALIGNMENT_16K`, сертификат загрузки Google Play и параметры OTA зарегистрированного Android-дескриптора. App Links проверяются также с отпечатком **Play App Signing** из Play Console. После приёмки на устройстве заменить пакет в черновике Alpha и проверить статус декларации фотографий и видео. Декларации фоновой геолокации и foreground services проверяются отдельно.
