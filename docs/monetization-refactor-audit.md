# GAFUS Main — рефакторинг монетизации (2026-10-15)

## Решения и границы изменений

Единый источник серверных прав: `packages/core/src/services/contentAccess/policy.ts`
и проверка отдельных шагов через `services/contentAccess/index.ts`.
Web и Mobile используют серверные функции, а не клиентские признаки покупки.

- Обычные публичные платные курсы: действующая подписка или предусмотренная роль
  (ADMIN, TRAINER, PARTNER); флаг аварийного отключения проверки подписки сохранён.
- Будущие публичные бесплатные курсы: доступны без подписки.
- Приватные курсы: только назначенные студенты (`CourseAccess`); подписка,
  Гафусы, рекламное видео и аварийный переключатель не открывают чужой курс.
- Статьи: только подписка/предусмотренная роль; отдельная рекламная разблокировка
  `ARTICLE` по времени продолжает работать на Mobile.
- Отдельные шаги платного обычного курса: подписка, Гафусы или rewarded-разблокировка
  именно этого шага. Контент неразблокированных шагов вырезается сервером.
- Мини-гайды: исходная механика сохранена без расширения прав на платные/приватные.
- Права чата кинолога и консультаций **не** зависят от Гафусов или рекламы;
  существующая бизнес-логика отдельных планов подписки сохранена.
- Прогресс, роли, ежедневный курс, офлайн-механика и серверный кэш учебного
  содержимого сохранены. Положительные решения о доступе не кэшируются на 5 минут.
- Проверки получения видео/HLS через Web и API перепроверяют право доступа
  при обращении; метаданные видео кэшируются отдельно от решения авторизации.
- Персонализированные списки дней и статей больше не сохраняют серверное
  решение о доступе в пяти-минутном Next.js `unstable_cache`.
- Статьи без подписки не отдают `videoUrl` и полную фотогалерею в API;
  для карточки каталога разрешена только первая фотография-обложка.
- Защищённые HLS-сегменты через Web/API имеют `Cache-Control: private,
  no-store`, поэтому прокси и браузеры не сохраняют их на год, минуя повторную
  проверку прав. Приватные заголовки также выставлены для списка статей.
- Привилегированные роли ADMIN/TRAINER согласованы на уровне курса, отдельных
  шагов, видео и rewarded-проверок без изменения мини-гайдов.
- Закрыт IDOR в Web Server Actions: ID пользователя для выдачи курсов,
  приватных назначений, избранного, уроков и статей всегда сверяется
  с реальной сессией; подставленный `userId` не открывает чужие права.
- На страницах `/courses` и `/favorites` отключена пяти-минутная RSC
  ревалидация; каталог для гостя остаётся доступен без персональных прав.

## Prisma — безопасный переход

Миграция: `packages/prisma/migrations/20261015050000_subscription_only_monetization/migration.sql`.

Она транзакционно архивирует исторические платежи, права покупателей,
акцепты оферты, старые цены и Apple Product ID в
`gafus_legacy_purchase_archive` **до** удаления прежних таблиц/полей.
Архивные enum-поля преобразуются в текст. В `CourseAccess` оставляются
**только** записи назначения приватных курсов. Таблицы платежей по
действующим подпискам, самих подписок и прогресса обучения не изменяются.
В SQL заданы `lock_timeout=10s` и `statement_timeout=120s`.

На отдельной локальной PostgreSQL протестированы заполненные платёжные
таблицы, архивирование курсовых и статейных цен, сохранность назначения
на приватный курс и удаление фиктивного покупательского назначения.
Проверка `prisma migrate diff` между итоговой БД и новой схемой:
`No difference detected`.

**Историческое ограничение:** последовательность ВСЕХ старых миграций
из пустой базы на локальном экземпляре завершается ошибкой ещё до этой
миграции — ранняя `20241108120000_exam_result_trainer_review` ожидает
отсутствующую таблицу `ExamResult`. Новая миграция отдельно успешно
проверена на копии **структуры** актуальной локальной PostgreSQL.
Это ограничение не следует путать с результатами на существующей БД.

## Ограничение прямых CDN-ссылок на HLS

Mobile API по текущей архитектуре переписывает HLS-манифест, выдавая прямые
presigned Object Storage URL для тяжёлых сегментов. Их TTL равен
`VIDEO_PLAYBACK_TOKEN_TTL_MINUTES = 720` (**12 часов**). Новые обращения за
манифестом и старые проксируемые сегменты проверяют доступ, но **уже
выписанные прямые ссылки на медиа невозможно немедленно отозвать** через
изменение подписки в PostgreSQL. Этот риск существовал в системе доставки видео;
не следует трактовать серверные регрессионные тесты как гарантию немедленного
отзыва уже подписанных CDN URL. Переход на проксирование всех сегментов с
проверкой прав потребует отдельного нагрузочного и нативного тестирования;
самостоятельно менять production-медиатрафик в этом рефакторинге нельзя.
