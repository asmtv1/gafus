# Посещения врача

В Web и Mobile раздел расположен в карточке своего питомца между «Записи о процедурах» и «Вес» и открывает отдельный экран.

Обязательны дата (без времени) и специальность врача. ФИО, клиника, диагноз, заключение и заметки необязательны. Записи сортируются по дате посещения от новых к старым, раскрываются для просмотра и редактируются. Удаление требует подтверждения.

На запись разрешено до пяти вложений: JPEG, PNG, WebP и PDF, до 10 МБ каждое. Mobile поддерживает фотогалерею, камеру и выбор файла. Изображения открываются отдельно; оригиналы можно скачать. Вложения не появляются в разделе «Документы» и не расходуют квоту фотоальбомов.

## Доступ и хранение

Каждый запрос проверяет владельца питомца и принадлежность посещения/вложения. DTO не содержит ключи хранилища. Ответы API используют `private, no-store`; Web mutations защищены CSRF, Mobile использует Bearer и штатное обновление токена.

Файлы находятся в уже существующем **закрытом** bucket галереи:

`users/{ownerId}/pets/{petId}/vet-visits/{visitId}/{attachmentId}/original.{jpg|png|webp|pdf}`

Изображения сохраняются без изменения оригинала. Превью `thumb.webp` создаётся отдельно (до 640 px, WebP 85) и выдаётся через существующий защищённый CDN на 120 секунд. Оригинал выдаётся по подписанной ссылке Object Storage на 60 секунд: это позволяет скачать файл до 10 МБ без ограничения размера ответа функции CDN origin. PDF не имеет растрового превью. Mobile не сохраняет просмотренные изображения в постоянный дисковый кэш; временная копия скачивания удаляется после сохранения/отправки.

Перед сетевой загрузкой резервируется durable cleanup job. Публикация вложения повторно проверяет владельца и число вложений под блокировкой. Загрузка не удерживает блокировки БД. Неудачные и незавершённые загрузки удаляются worker после десяти минут. Удаление вложения, посещения, питомца или аккаунта сохраняет задания очистки в той же транзакции, что и удаление записей. Прямой доступ к закрытому bucket и раздача оригиналов через CDN origin запрещены.

## Выпуск

1. Применить миграцию `20261010150000_pet_vet_visits` после предыдущих миграций галереи.
2. Применить обновлённую политику bucket из `infra/gallery/main.tf`: Web получает Put/Get только для оригиналов посещений и Put для превью; worker — Get/Delete для очистки; origin — Get только для превью. Новые bucket/CDN не создаются.
3. Пересобрать и выпустить gallery cloud functions: allowlist ключей должна разрешать превью посещений в origin и оригиналы в cleanup worker.
4. Выпустить Web/API и Mobile. Используются существующие `GALLERY_BUCKET`, `GALLERY_S3_*`, `GALLERY_CDN_BASE_URL`, `GALLERY_CDN_SECRET`. Хранилище никогда не переключается на публичный bucket при недостающей конфигурации.
5. Проверить на реальной среде: загрузка/просмотр/скачивание JPEG и PDF; отказ другому аккаунту; отказ прямому неподписанному запросу; истечение подписанных ссылок; шестое вложение; очистка после удаления посещения и питомца.

Применение миграции, Terraform и выпуск в production требуют отдельного разрешения; локальные проверки не подтверждают рабочее облачное окружение.

## Локальная проверка

Миграция применена к отдельной временной PostgreSQL-базе. Девять интеграционных тестов проверяют CRUD, владельца, фактический тип и размер файла, конкурентную загрузку последнего свободного вложения, выдачу медиа и задания очистки при удалении вложения/посещения/питомца/аккаунта. Сетевые операции с облаком в этих тестах заменены заглушками.

Прошли проверки типов Web, Mobile, API и Core; проверки схемы Prisma, форматирования Terraform и изменений. Связанные наборы галереи: storage — 30 тестов, cloud — 41, выбранные core — 24 (ещё 20 существующих интеграционных тестов галереи пропущены без их отдельной среды).

Web проверен в браузере на ширине 390 и 1440 px, Mobile — на симуляторе iPhone 17. Использовались реальные компоненты и локальные вымышленные данные: изображение, PDF, длинное имя файла, раскрытие и редактирование записи, видимая ошибка/повтор сохранения, защита черновика при выходе. В Web отдельно проверена отмена перехода назад и вперёд с сохранением текста и выбранного файла. В просмотрщике Mobile проверены безопасные отступы и открытие оригинала изображения. Камера, системное сохранение/отправка файлов, Android и рабочая CDN-среда требуют проверки при выпуске.
