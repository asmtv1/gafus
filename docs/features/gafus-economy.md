# Гафусы — инженерная готовность и порядок безопасного запуска

> Код реализован в локальной рабочей ветке **без Codex**. Никакие команды развертывания, применения миграции к production, git push или массового коммита не выполнялись.
> Это не разрешение автоматически включать валюту на production. База должна быть мигрирована **до** запуска новой версии backend.

## Реализованная функциональность

- **Prisma и PostgreSQL:** добавочная миграция `20261010190000_add_gafus_economy` (11 таблиц), проверка неотрицательного баланса, связности журнала операций, уникальных ключей идемпотентности.
- **Кошелёк:** транзакционный ledger, сериализация по пользователю через advisory lock, история, стоимость и срок доступа из настроек, запрет переполнения `INTEGER` и несоответствия направления операции.
- **Начисления:** подходящие по содержанию публикации, вопросы и ответы; не более 3 обычных Гафусов за скользящие 24 часа по умолчанию; бонусы за каждое новое кратное порогу количество **уникальных неавторских реакций** и за каждый впервые выбранный лучший ответ. Начисления идемпотентны. Предыдущие посты и отредактированные посты не создают задних начислений.
- **Доступ:** платный/приватный контент нельзя покупать за Гафусы; единый серверный entitlement для обычного курса и мини-гайда; привязка платного шага к `dayOnCourseId + stepOnDayId`, автоматическое истечение (7 дней по умолчанию). Серверные чтения, выполнение шагов, экзамены, выдача видео и offline-путь проверяют entitlement.
- **Web и Mobile:** кошелёк, история, покупка шага, каталог мини-гайдов, защищённый просмотр HTML после проверки доступа, индикатор реакций у автора поста. Автор мини-гайда может вводить HTML в редакторе курса.
- **Администратор:** страница `/main-panel/gafus`, настройки с ревизией, ручная корректировка кошелька и аудит, очередь антифрод-сигналов с ручным отклонением/подтверждением и возвратом не более доступного баланса.
- **Антифрод:** требования к содержанию, отпечатки для защиты от повторов, пороги активности и мягкий сигнал `REACTION_BURST` при подозрительном темпе реакций. Сигнал сам по себе **не списывает** деньги.
- **Уведомления:** transactional outbox для бонусов, воркер с `SKIP LOCKED`, claim lease, повторными попытками и защитой от доставки сообщений старше 48 часов. Включается отдельно.
- **Переход со старой rewarded-рекламы:** флаг отключения новых рекламных сессий и старых трат, admin-only preflight, ручные партии до 50 кошельков, перевод 1:1 с идемпотентностью и аудитом. Старые записи не удаляются.

## Переключатели экономики (по умолчанию включены) и отдельные защитные флаги

| Флаг | Значение | Назначение |
| --- | --- | --- |
| Настройка `economyEnabled` | `true` | Общий переключатель новой экономики |
| Настройка `earningEnabled` | `true` | Начисления за активность и бонусы |
| Настройка `spendingEnabled` | `true` | Покупка доступа |
| `GAFUS_NOTIFICATIONS_ENABLED` | Не задан | Запуск cron-воркера бонусных push |
| `GAFUS_LEGACY_REWARDED_DISABLED` | Не задан | Выключить **новые** ad sessions и старую трату кредитов, сохранив завершение уже выданных ad sessions |
| `GAFUS_LEGACY_IMPORT_ENABLED` | Не задан | Разрешить отдельное ручное действие импорта (без отключения рекламы импорт не сработает) |

**После первого деплоя новая экономика активна сразу**, если в `GafusSettings` ещё нет записи `key=default`: начисления, списания и общая экономика имеют значения `true` в Core, Prisma и миграции. Если администратор уже сохранил настройки в БД, его решения не перезаписываются: существующие значения могут быть `false`.

**Критически важно:** после импорта хотя бы одного старого кошелька нельзя повторно разрешать старую трату кредитов: старые записи сохранены для аудита, иначе средства можно израсходовать дважды. Никогда не запускайте импорт в процессе активных возвратов или незавершённых рекламных сессий.

### Проверка конкурентных транзакций на выделенном тестовом PostgreSQL

Использовать исключительно disposable локальную БД **`gafus_test`** с полной актуальной Prisma-схемой. Никогда не подставлять `DATABASE_URL` production вместо `GAFUS_TEST_DATABASE_URL`.

```sh
# DSN специально выделенной локальной тестовой базы, не production:
export GAFUS_TEST_DATABASE_URL="$LOCAL_GAFUS_TEST_DSN"
DATABASE_URL="$GAFUS_TEST_DATABASE_URL" pnpm --filter @gafus/prisma exec prisma db push --skip-generate
pnpm --filter @gafus/core exec vitest run --config vitest.config.ts src/services/gafus/gafus.postgres.test.ts
```

Проверено на выделенной локальной базе 11 октября 2026: 5 конкурентных событий активности → ровно 3 начисления, 5 одновременных списаний из баланса 4 → 4 успешных и 1 отклонённое, отсутствие отрицательных балансов и расхождений ledger. **Важно:** для совершенно новой пустой БД исторический `migrate deploy` напрямую не подходит (первая миграция требует уже существующую `ExamResult`); используйте `packages/prisma/scripts/bootstrap-fresh-postgres.sh`. Для уже развёрнутых БД по-прежнему применяется `prisma migrate deploy` после сверки их истории.

## Безопасная последовательность выкладки

1. Сохранить/изолировать накопившиеся параллельные незакоммиченные изменения. Произвести ревью точного diff системы Гафусов, без `git add .` или случайного объединения посторонних функций.
2. Прогнать базовые typecheck/build и все модульные + PostgreSQL интеграционные тесты в CI/staging; отдельное исправление `PublicPet` уже устранило ошибку TypeScript без расширения публичного DTO.
3. На staging сверить миграцию со всеми уже действующими миграциями. **Сначала** применить Prisma миграции к staging/production, **затем** доставить обновлённые Core/API/Web/admin/worker, затем Mobile. Не выкладывать backend раньше таблиц экономики, так как публикации/вопросы обращаются к ним даже при выключенном общем флаге.
4. Сразу после деплоя убедиться, что `/api/v1/gafus/status` возвращает `enabled.economy=true`, `enabled.earning=true`, `enabled.spending=true` при отсутствии ранее сохранённых администратором настроек. Сохранённые записи с явным выключением остаются в силе и не сбрасываются деплоем. Проверить совместимость старого контента, платных курсов, подписки и ежедневных курсов.
5. В staging на тестовых аккаунтах проверить 3 за 24 часа, бонус 10/20/30 уникальных реакций, лучший ответ, повторные запросы, блокировки, недостаточный баланс, 7-дневный TTL, платные/приватные курсы, HTML мини-гайды, видео, экзамены, ручные корректировки, антифрод и push.
6. Все три флага по умолчанию уже включены: сразу после релиза отслеживать начисления, списания, состояние ledger и ошибки доступа. Для немедленной остановки вручную выключить нужные переключатели через админ-панель.
7. Когда клиент с валютой доступен пользователям, отдельным этапом отключить **новые** старые рекламные сессии (`GAFUS_LEGACY_REWARDED_DISABLED=true`). Дождаться отсутствия активных ad sessions и нерешённых возвратов. Затем временно выставить `GAFUS_LEGACY_IMPORT_ENABLED=true`, пройти preflight и вручную запускать партии через админку. Сверить суммы и аудит, после окончания выключить флаг импорта.
8. Включить `GAFUS_NOTIFICATIONS_ENABLED=true` только после проверки push-подписок и воркера, проследить за `PENDING/PROCESSING/FAILED`. Оповещения старше 48 часов не доставляются.
9. Для отката приложения выключить начисления/списания/экономику через настройки и отдельно уведомления через ENV; не откатывать схему БД, пока есть новые финансовые записи. После импорта **не включать** старую трату rewarded-кредитов.
