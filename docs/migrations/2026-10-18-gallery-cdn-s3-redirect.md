# Gallery: Beget CDN → GAFUS API 307 → private Cloud.ru S3

**GAFUS Main, branch `main`. Status: metadata migration completed and checked on production on 2026-10-18; CDN cutover NOT performed. Code remains local and unpushed.**

## Invariants

- Gallery stays in `gafus-gallery-private`. **No public bucket policy.** Do not create a second bucket or copy Gallery media elsewhere.
- `posts`/Feed and Questions CDN remain unaffected; keep `gafus-gallery-origin` running until AFTER verified production cutover.
- GAFUS API signs the origin request and answers HTTP 307; **never reads/streams image bytes**. Beget must follow redirects itself and cache the WebP, not the S3 URL. S3 Get/Head presigns expire after 60 seconds.
- Existing clients still receive the current Gallery DTO shape and `/md5(token,expiry)/...` Beget link format. No Expo OTA or new Android/iOS build is part of this migration.
- Enforce Beget Secure Token at CDN edge even for `HIT`. Old Mobile's `scopedMediaCacheKey` and `mediaCdnKindFromSignedUrl` hardcode the **OLD** Beget host: with a new host, legacy mobile may fall back to memory-only images and lose circuit-breaker behavior. **Old installed binaries require real-device checks; static TypeScript tests are insufficient.** The owner expressly elected to perform this AFTER deployment, with the existing Gallery Origin retained for immediate rollback. Never label deferred checks as passed.
- Original veterinarian documents and incoming/uploads/attempts remain `private, no-store`, never enter CDN.
- Two different secure keys: old Gallery Beget token uses `GALLERY_CDN_SECRET`, new Beget token uses `GALLERY_CDN_REDIRECT_SIGNING_SECRET`. The new static origin header uses separate `GALLERY_CDN_REDIRECT_ORIGIN_SECRET`. Do not substitute one for another or print into logs.

## Browser cache correction (2026-10-18)

The isolated CDN correctly cached from `api.gafus.ru` with `Cache-Control: public, max-age=600` but Beget `caching_time_browser={enable:true,time:180}` and `static_response_headers` accepted in API still **did not** rewrite the emitted client header (remained 600). An isolated Nginx response with `Cache-Control: public, max-age=180, s-maxage=600, must-revalidate` preserved Beget `HIT` and exposed `max-age=180` to clients. This uses standard shared-cache `s-maxage` semantics and does not require unsupported Beget response rewriting. CDN browser override and static headers have therefore been disabled on the isolated CDN; origin S3/WebP metadata controls the browser policy. No end-user content was used in these smoke tests.

The production Gallery FINAL WebP metadata was initially updated to `public, max-age=600` and then **all seven files were successfully updated again** using conditional same-bucket self-copy. The final verified header is `public, max-age=180, s-maxage=600, must-revalidate`. Job `92dbbe68d2a5852f` changed all seven and verified each ETag and length; separate read-only job `bb85a93f48c686a8` confirmed all seven WebP (285,906 bytes), four Public Access Block controls and no synthetic objects. The new CDN now relies on this Origin Cache-Control header, with its `caching_time_browser` and `static_response_headers` overrides **disabled** (API readback confirmed). A synthetic Nginx GET returned this exact header and `HIT` through Beget. `GALLERY_CDN_BROWSER_CACHE_VERIFIED` and `GALLERY_CDN_METADATA_MIGRATED` must remain false in protected release variables until real permanent API route, browser logout/session tests, and an updated inventory immediately before cutover pass.
