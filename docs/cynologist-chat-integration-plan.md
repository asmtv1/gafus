# Чат с кинологом: контракт интеграции

Актуализация: 2026-10-01. Продуктовые требования взяты из согласованного плана «чат с кинологом.md». Инструкции о моделях и сабагентах в исходном документе не являются частью бизнес-логики.

## Требования


- Чат работает в вебе и мобильном приложении. Кинолог получает отдельную вкладку «Диалоги» в этих же приложениях.
- Чат независим от консультаций: не создаёт бронирований, слотов или созвонов.
- Доступ к чату: месячный, трёхмесячный, партнёрский и пожизненный. Пробный доступ не включает чат.
- Консультации доступны только по действующему трёхмесячному тарифу. Новые правила применяются сразу ко всем пользователям, без сохранения старых условий.
- Один постоянный приватный диалог на клиента с назначенным кинологом.
- Перед первым сообщением клиент самостоятельно заполняет обязательную анкету. Анкета становится первым сообщением и больше не запрашивается, включая продление тарифа.
- После окончания доступа клиент читает историю и ответы, но не отправляет сообщения и вложения. Кинолог может ответить на ранее полученный вопрос. Продление открывает отправку в том же диалоге.
- В интерфейсе: «Ответ в течение суток» и «Кинолог отвечает в рабочие дни с 10:00 до 19:00 МСК». Автоматического SLA, дедлайнов и контроля просрочки нет.
- Текст, фото до 10 МБ, видео до 100 МБ и двух минут. Хранилище — Stream CDN.
- Клиент получает push об ответе, кинолог — о новом сообщении. Дополнительные напоминания кинологу идут каждые пять часов, только по будням с 09:00 до 21:00 МСК, по одному на диалог с непрочитанными сообщениями. Прочтение прекращает напоминания.

В первом выпуске не добавляем повторные анкеты, выбор питомца, звонки внутри чата, голосовые сообщения, произвольные документы, ветки обсуждений, редактирование и удаление сообщений пользователями.


## Реализация

- Чистые поля, ограничения, Zod-схема и формат первого сообщения: `packages/consultation-shared/src/intake.ts`. Консультации расширяют эту же схему идентификатором слота и ключом идемпотентности.
- DTO прав, состояния и сессии: `packages/consultation-shared/src/cynologist-chat.ts`. Нет дедлайнов, просрочек, повторных анкет или зависимости от бронирований.
- Права считаются по всем действующим подпискам в `getCynologistEntitlements`. Роль PARTNER проверяется в БД. Пожизненный доступ даёт чат; консультации требуют отдельного действующего непробного THREE_MONTHS.
- GAFUS хранит диалог, назначение, анкету, этап создания, отправки, принадлежность вложений и служебные события. Сообщения хранятся в Stream CDN/Chat.
- Уникальные ключи клиента, канала, первого сообщения, операции отправки и уведомления защищают от конкуренции и повторов. Неоднозначная отправка сверяется через GetMessage.
- Отдельные role `gafus_chat_reader` и channel type `gafus_cynologist`. Пользовательская роль без глобальных grants; только членство даёт чтение/события. Создание канала, изменение участников, отправка и загрузки через сервер GAFUS.
- Перед выдачей JWT проверяются реальные grants и включённые authentication/permissions checks. JWT на один час, refresh через авторизованный endpoint.
- Флаг CYNOLOGIST_CHAT_ENABLED закрывает новые старты, отправки и загрузки; существующая история и сессии чтения остаются доступны. Назначение — CYNOLOGIST_CHAT_TRAINER_USER_ID, без автоматического выбора TRAINER.

## API

Одинаковый контракт: web `/api/v1/cynologist-chat`, mobile на apps/api с Bearer JWT.

| Метод | Суффикс | Назначение |
|---|---|---|
| GET | пустой | состояние, права, сохранённая анкета |
| POST | /start | первая анкета и восстановимое создание |
| POST | /session | пользовательский JWT, чтение после истечения |
| POST | /messages | text, attachmentIds, clientMessageId UUID |
| POST | /attachments | один multipart файл; поток, magic MIME, ffprobe |
| DELETE | /attachments | отмена ещё не использованного вложения |
| GET | /dialogs | назначенному кинологу, курсор, непрочитанные |

Для открытия конкретного диалога кинологом — `?chatId=...`, проверка принадлежности на сервере. Ответы no-store, web-мутации защищены CSRF. Общие Redis-лимиты срабатывают для session/send/upload. Произвольные ссылки и sender/user/channel IDs клиент не задаёт.

Webhook: POST `/api/v1/stream-chat/webhook` на apps/api, HMAC по исходному телу. В inbox сохраняются идентификаторы и время, без копии текста/анкеты. BullMQ обрабатывает события и сверяет актуальное чтение перед напоминанием; серия не перезапускается дополнительными сообщениями.

## Экраны

- Web: `/cynologist-chat`, `/cynologist-chats`, `/cynologist-chats/[chatId]`. Динамический SDK, общие кнопки GAFUS, актуальные цвета.
- Mobile: отдельная вкладка «Чат» в нижнем меню клиента между «Кинолог» и «Профиль»; у назначенного кинолога вместо неё «Диалоги». URL `/cynologist-chat` сохранён. В web — отдельный пункт основного меню. В профиле обеих платформ входа в чат нет. SDK-хук подключения/очистки, неперсистентная сессия, фон и кнопки GAFUS.
- Формы показываются один раз; повтор частично завершённого старта использует уже сохранённую анкету.
- Истечение: видна история и предложение продлить; send/upload сервером запрещены. Продление сохраняет диалог.
- Диалоги кинолога: сначала непрочитанные серии, затем последняя активность; пустое состояние и курсор.
