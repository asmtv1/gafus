## Блокеры для безопасного merge

1. **Секрет в истории и индексе.** Git отслеживает файл Apple `.p8` в каталоге `secrets/`. Добавление `.gitignore` само по себе не удаляет уже отслеживаемый файл из индекса и истории. До публикации требуется отдельно прекратить отслеживание, проверить Git-историю, определить необходимость ротации ключа и настройку secure storage в CI. В этой уборке секрет не читался, не выводился и не переписывался.
2. **Неподготовленный Git index.** Новые исходники и миграции находятся среди неотслеживаемых файлов; вместе с ними — тысячи исторических API QA-артефактов. Исторические каталоги API `apps/api/g[0-9]*/`, `w1-*` и аналогичные исключены из Git, но сохранены локально. Не использовать `git add -A` вслепую: сначала отдельно сформировать allowlist исходников, тестов, миграций, конфигурации и актуальной документации; затем проверить `git diff --cached --name-status`, отсутствие секретов и крупного бинарного мусора.
3. **QA readiness: NO.** Несмотря на unit/mounted PASS для Web/Mobile и отдельные PASS Admin/Trainer, текущий `docs/qa/CURRENT_RELEASE_STATUS.md` оставляет непроверенными native offline/video, provider-сценарии и часть Web/Admin/Trainer. Очистка не заменяет финальные сборки и функциональный QA.
4. **Git deletion review.** Ранее удалённые файлы (включая Next.js legacy) требуют просмотра по назначению и проверок сборки перед переносом. Не восстанавливать и не удалять автоматически без оценки зависимости.
