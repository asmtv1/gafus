# GAFUS — переход с VK OAuth и удаление iOS REVIEW/RELEASED

Статус: только изолированная локальная ветка. Ни API, ни Web, ни новая native-сборка,
ни Prisma migration на PROD ещё не выкатились.

## Правила

- Для iOS, Android, Web — одна конфигурация без review/released профилей.
- Удалён действующий VK OAuth; старые SDK получают HTTP 410 VK_AUTH_RETIRED.
- Сохранять User, Account (старые VK-привязки), активные подписки, платежи,
  курсы, прогресс, собак и публикации. Не очищать ссылки на VK в чужих постах.
- JWT, refresh, email password reset, Apple IAP и обязательная версия OTA остаются.
- ЮKassa на iOS — самостоятельный аудит правил Apple, не часть этой миграции.

## Аккаунты и поддержка

Предыдущий агрегированный снимок: 654 VK-связанных пользователя; 564 без пароля,
из которых 404 с email и 160 только с телефоном; 3 с действующими подписками.
Перед запуском повторно проверить цифры в агрегатах, не выгружая PII.

1. На тестовом аккаунте с VK Account и без passwordSetAt проверить сброс
   пароля по email, установку нового и вход с тем же User.id.
2. Проверить сохранение UserCourse, Pet, AppSubscription и покупок.
3. До отключения VK подготовить заметное сообщение о смене способа входа.
4. Для аккаунтов без email — поддержка с независимой проверкой личности,
   аудитом передачи доступа и отдельной защитой оплаченных подписок.
   Знания имени пользователя или номера телефона недостаточно.
5. Не менять пароли и не рассылать сообщения массово без решения владельца.

## План выкладки после завершения работы агента OTA/платежей

1. Содержательно объединить ветку с его незакоммиченными изменениями:
   конфликт возможен в schema.prisma, mobile native scripts, OTA, подписках.
   Эта ветка сама по себе их НЕ содержит.
2. Снять резервную копию PostgreSQL, проверить её восстановление и зафиксировать
   Prisma migration state, а также зарегистрированные версии OTA.
3. Применить миграцию сначала к изолированной копии PROD и сверить
   агрегированные counts User, Account, AppSubscription, UserCourse и Pet.
4. В согласованное окно переключить Web, API и админку; убедиться, что
   восстановление пароля работает и старые VK endpoints возвращают 410.
5. С нуля регенерировать Expo native, собрать отдельный IPA и AAB.
   При необходимости iOS 1.7.5 (99) вместо IPA (98) и Android versionCode
   выше последнего RuStore релиза — после проверки фактических номеров
   последних загруженных сборок.
   Произвести новый native fingerprint; старый IPA не обновлять через
   неподходящий обязательный OTA.
6. Проверить на физических iPhone/Android вход, восстановление,
   токены, выход, профиль/питомцев/курсы/покупки, Apple IAP restore,
   обязательный OTA для новой native версии. Не расширять OTA за
   admin и asmtv1 без отдельной команды.
7. После отключения всех зависимых OAuth процессов очистить PROD/GitHub
   VK secrets и внешние VK ID callback URLs, затем отозвать ключи.

## Локальные проверки, которыми закрываем регрессию

- Prisma generate/validate и изолированная PG18 с исходной схемой.
- scripts/qa/vk-review-schema-isolated-pg.sh — до миграции создаёт
  историческую VK Account связь, активную Apple подписку и прогресс курса,
  после миграции проверяет их сохранение и ревизию OTA.
- Проверка native Expo схем и JS/Hermes: apps/mobile/scripts/verify-no-vk-auth.mjs
- pnpm check:core-boundaries, typecheck, Vitest API/Mobile/Core/Web/Admin,
  Expo export и сравнение release manifests.

## За пределами этой работы

PROD backup, реальная миграция, подписанный IPA/AAB, проверка Apple IAP
на устройстве, публикация App Store/RuStore, массовые OTA, уведомления
пользователям и отзыв ключей. Все они требуют отдельного релизного окна
после объединения с изменениями агента OTA/платежей.

Rollback: никакого нового скрытого профиля REVIEW/RELEASED. Применять
согласованный rollback приложения + восстановление проверенного backup,
если потребуется восстановить удалённые временные VK-таблицы.
