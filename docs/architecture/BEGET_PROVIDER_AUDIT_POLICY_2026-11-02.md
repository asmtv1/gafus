# Beget control-plane checks vs ordinary GAFUS releases

- **Every `main` CI/CD release:** validate configured approvals and secrets locally (`beget-release-readiness.mjs` and `checkGalleryRedirectConfig`). Do not call the Beget control-plane (`api.beget.com`) or CDN delivery hosts for ordinary application-only changes. Beget outages must not block unrelated application fixes.
- **Provider configuration changes in source:** `beget-provider-change-detect.mjs` compares push `before` and current SHA. Changes to CDN provisioning/configuration scripts, Gallery provider validation, or relevant production Compose CDN environment bindings require live Beget API and Feed/Gallery delivery checks **before** deployment, plus post-deployment delivery verification. Detection errors block release, not silently skip it. This does not change provider settings.
- **Out-of-band changes** (Beget console/API, GitHub production CDN variables): before treating those changes as approved, run **Actions → Beget Provider Audit → Run workflow** on `main`. Those edits do not generate a Git push and cannot be reliably inferred from source diffs.
- **Every day:** `Beget Provider Audit` runs at 03:17 UTC, independently from CI/CD and manual Deploy Only. It verifies the Beget control plane and real Feed/Gallery delivery. Its failure is visible in that workflow but does not block unrelated application releases.
- **Manual Deploy Only:** only already-built, CI-verified image SHA releases; checks local Gallery configuration but does not query Beget CDN delivery or provider control-plane settings. Run the separate Beget Provider Audit to verify real Feed/Gallery delivery; Deploy Only does not authorize CDN configuration or 11 Cloud.ru Jobs changes.
- **Safety:** provider/API token failures do not turn into success on a configuration change. Gallery remains private; no Yandex fallback, no S3/Beget changes by the audit. The control plane and data plane are deliberately separated.
