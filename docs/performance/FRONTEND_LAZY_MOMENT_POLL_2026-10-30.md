# P2 implementation — lazy `MomentPoll` только для публикации с опросом

**30.10.2026.** Web UI + focused Web tests only; **no API, Worker, Docker, Types, Core, media ACL, manifests, shared config, production or Git staging**. Measured against the accepted **existing** Web `dist` snapshot before source changes; a distinct scratch-only Web build after source changes was used for the repeat CDP measurement. Both browser runs used the **same synthetic read-only video post with `hasPoll=false`**. A supplemental after-only `hasPoll=true` browser scenario proves the poll chunk actually loads when needed. **READY=NO** for the overall release.

## Justification and implementation

- **Original import graph was truly eager:** `App.tsx` lazy-imports `/moments` `MomentsCatalog`, which statically imports `MomentSummary`, which previously statically imported `MomentPoll` even when `post.hasPoll=false`. Before-capture Chrome **requested `MomentPoll-BNnsVqGH.js`** (~11,118 B gzip, 35,758 B raw) on a single synthetic **video-only/no-poll** post. Thus the split was not imaginary or already complete.
- Changed **only** `apps/web-vite/src/features/moments/MomentSummary.tsx`: `React.lazy(() => import('./MomentPoll'))` inside the existing `post.hasPoll` condition; `Suspense` uses the existing compact `Loading` and message **«Загружаем опрос…»**. A local class error boundary leaves the surrounding post, author, actions and comments accessible on a failed chunk and offers **«Перезагрузить страницу»**. A cached rejected dynamic import cannot be fixed by repeated immediate retries. Keying the boundary by `userId:post.id` resets failure state on actor/post changes. `MomentPoll.tsx`, its query keys, vote/check/cancel/close permissions and API contracts are **unchanged**; details route retains its own separate direct import.
- Changed only related Web tests: an existing inline poll test waits for the actual post-Suspense commit; new `MomentSummary.lazyPoll.test.tsx` probes that a no-poll card **never evaluates the lazy module, never mounts poll, never performs poll HTTP**, followed by a poll that loads the **actual original module** and successfully issues the existing one-vote POST; new `MomentSummary.lazyPoll.error.test.tsx` simulates a rejected chunk and proves the rest of the post plus recovery UI stay visible. The previous MomentPoll vote, permissions, manual-close and image tests are preserved.

## Actual Chrome CDP before/after numbers

Measured bytes below are **sum of all actual JS + CSS requests on the indicated phase**. Gzip = HTTP compressed response body (`Content-Length`), raw = bytes of built files before compression. No speculative asset list or single-entry estimate. Browser: headless Chrome 156, new isolated profile for each cold scenario, loopback HTTP with identical synthetic read-only API and gzip settings, external requests CDP-blocked, shared Vite 5173/Hono 3001 not accessed. Distinct snapshots: original `apps/web-vite/dist` (index SHA-256 `22e313ea4d616ea885163b23cd01a3911dbd9976c359307f35c731c797989e81`) and **separate**, scratch-only `.local-pg-scratch/agent3-perf-20261030/web-dist-after`.

**Decode difference on cold `/moments`:** JS raw **479,336 → 468,446 B (−10,890 B)**; CSS raw **226,113 B unchanged**. Requests remained **28 JS + 9 CSS**, because the bundler changed how shared code is grouped; the positive benefit is fewer transferred bytes and **zero `MomentPoll-*.js` requests on no-poll cards**, not necessarily fewer overall requests. Importantly, the old **~11.1 KB gzip poll-named chunk was not a fully removable independent block**: after rebuilding, other shared chunks absorbed some code. The **actual measured cold-route saving is only ~2.7 KB gzip**, not 11.1 KB. No false 11 KB saving claim.

**Positive poll path, after-build, separate synthetic case:** same video post with `hasPoll=true` → Chrome loads `MomentPoll-BEsRNBKe.js` **HTTP 200**, **12,807 B raw / 4,630 B gzip**, additionally performs `GET /api/v1/feed/posts/PERF_POST_1/poll`, mounts the real poll component with its form/options, and no HLS. The after-build no-poll case requests **no** `MomentPoll-*.js` and performs **no** poll GET. Existing Web UI tests additionally confirm an actual vote POST via the unchanged poll implementation. The after-build cold `/moments` **with** a poll costs **198,515 B gzip JS+CSS**, compared to **193,885 B** without it.

**Cache/MP4/HLS:** hashed assets have synthetic-preview `Cache-Control: public, max-age=31536000, immutable`; the browser's warm reload reuses cached JS as before, nonhashed `site-background.css` remains a small repeat request. On the synthetic video-only post `<video preload="none">` had no source before click; trusted CDP Play then fetched only local `clip.mp4`. New poll split does not load `hls-BIrUvssq.js` or `.m3u8`/segments before/after Play in the measured scenarios. Training HLS, real-device LCP/INP, CDN compression/cache and production API remain **not measured**.
