# GAFUS 1.7.3 — проверенные ссылки iOS Universal Links / Android App Links

**Решение владельца от 05.11.2026:** ссылки `https://gafus.ru/...` и `https://www.gafus.ru/...` на Моменты, вопросы, тренировки, чаты и восстановление пароля должны открывать соответствующие нативные экраны. В рамках подготовки изменены локальные исходники и CI, **никакого push, магазина, веб/production deploy не было**. Любые старые приложения до установки новой сборки продолжат жить со своими прежними настройками ссылок.

## Что реализовано

1. `apps/mobile/app.json`: 16 **узких**, `autoVerify=true` Android HTTPS intent filters — для apex и www, `/training/`, `/training` (точно), `/feed/`, `/questions/`, `/chats/`, `/moments/`, `/moments` (точно), `/reset-password` (точно). Каждый intent filter содержит **ровно один host и один path/prefix**, чтобы Android не смешал пути и домены из разных `<data>`. Сохранили существующий VK ID callback и приложение `ru.gafus.app`.
2. iOS `associatedDomains`: `applinks:gafus.ru`, `applinks:www.gafus.ru`. Прежний iOS подписанный IPA имеет TeamIdentifier `PJQ8PP666S` и application identifier `PJQ8PP666S.ru.gafus.app` (подтверждено локальной read-only проверкой embedded provisioning profile). Файл `apps/web-vite/public/.well-known/apple-app-site-association`: `appID=PJQ8PP666S.ru.gafus.app`, только разрешённые пути. Отдавать по HTTP(S) **без расширения, redirect, HTML, авторизации**.
3. Android `apps/web-vite/public/.well-known/assetlinks.json`: `package_name=ru.gafus.app`, `delegate_permission/common.handle_all_urls`, SHA256 **публичного** сертификата, извлечённого из фактически подписанного локального AAB от 04.11.2026: `4A:B5:16:CF:4F:E2:61:31:A7:14:D0:84:86:AA:6C:2B:10:70:1E:8D:4B:BD:20:B3:04:3D:64:99:C0:40:D8:F9`. Ни keystore, ни пароль не публиковались. **Внимание!** Это сертификат *upload/distribution AAB*. Google Play App Signing может подписывать поставляемые APK **другим сертификатом**. До Google Play rollout обязательно взять **App signing key certificate SHA-256** из Play Console и добавить в `sha256_cert_fingerprints` (если он отличается). Для RuStore/установок, подписанных сертификатом локального AAB, отпечаток совпадает. Это не гарантия верификации Google Play без фактического сертификата магазина.
4. `ci-cd/docker/nginx-vite-refactor.conf`: точные `location = /.well-known/apple-app-site-association` и `location = /.well-known/assetlinks.json`, `Content-Type: application/json`, `try_files $uri =404` — **никогда не возвращать Vite SPA HTML**. Активный внешний `ci-cd/nginx/conf.d/gafus.ru.conf`: на обоих доменах exact proxy к статическим файлам веб-контейнера, без redirect. Остальные маршруты, включая `/internal`, CDN и Chat2, не менялись.
5. `apps/mobile/src/shared/lib/links/verifiedAppLinks.ts` и `app/+native-intent.tsx`: безопасное преобразование проверенных HTTPS GAFUS URL в настоящие Expo Router маршруты, `/moments/:id` → `/feed/:id`, `/moments` → вкладку `/feed` (а служебные `/moments/new`, `/moments/saved`, `/moments/drafts`, `/moments/profile/:username` маршрутизируются на соответствующие существующие нативные экраны), `?commentId` и `?token=` сохраняются; чужие host/protocol/userinfo/путь не интерпретируются как trusted link. `reset-password` доступен даже при уже авторизованном пользователе и передаёт одноразовый токен на существующий экран восстановления (не логировать этот токен).
6. `ChatPushNavigation`: HTTPS ссылка на пост/вопрос/чат/тренировку, полученная когда пользователь не авторизован, запоминается в корневом компоненте и открывается после входа; при уже открытом экране избегаем повторного push. Доступ к закрытому чату или публикации **по-прежнему решает API/ACL**, URL никогда не выдаёт разрешение на чтение.

## Локально проверено

- На текущем **production gafus.ru и www.gafus.ru** ДО выкладки файлов оба endpoint отвечали `200 text/html` (SPA). Проверка шла только на чтение через AI Commander. **Это проблема действующего production, которую локальная правка сама по себе ещё не исправляет.**
- Изолированная production Vite build: **PASS**, реальные файлы 320 и 332 байта попали в `.well-known` итогового `dist`, сравнение исходник↔сборка байт в байт. В реальном локальном Nginx со скопированными файлами оба endpoint вернули `HTTP/1.1 200 OK`, `Content-Type: application/json`, `Cache-Control: public, max-age=300` без редиректа; `nginx -t` прошёл.
- `pnpm --filter @gafus/mobile exec vitest run src/shared/lib/links/verifiedAppLinks.test.ts src/shared/lib/utils/nativeIntent.g1.test.ts src/shared/components/ChatPushNavigation.nextParity.test.tsx --maxWorkers=1`: **60/60 PASS** (включая cold-start login, VK redirect и запрет внешнего host).
- `node --test scripts/qa/gafus-app-links-contract.test.mjs scripts/qa/gafus-app-links-live.test.mjs`: **10/10 PASS**, негативные проверки против HTML SPA, отсутствующего www, небезопасного appID/fingerprint.
- `node scripts/qa/verify-gafus-app-links.mjs --aab apps/mobile/build-android-20261104-local.aab`: **PASS по signer/AASA/source**, но старый AAB закономерно не содержит новых `/feed/`, `/questions/`, `/chats/`, `/moments/` и www native manifest paths — `node apps/mobile/scripts/verify-android-aab-app-links.mjs <old.aab>` возвращает **1** как должен. Новый AAB 1.7.3 будет проверен **после сборки**. Защита добавлена в `build-android-production-local.mjs` вместе с уже имеющимися AAB compressor/16KiB проверками.

## Перед включением production

1. Добавить/проверить **фактический Play App Signing SHA256** (не путать с upload key), если выпускаем приложение в Google Play. В RuStore проверить именно ключ устанавливаемого APK. Любой новый fingerprint включить в `assetlinks.json`. `node scripts/qa/verify-gafus-app-links.mjs` — исходные файлы; `--aab <путь>` — сертификат только данного AAB, не сертификат Play.
2. **Сначала** доставить обновлённые `apps/web-vite/public/.well-known/*` в release web image (`gafus-web`) и оба Nginx location (active edge + Vite internal), согласованным деплоем. CI выполняет blocking `--dist apps/web-vite/dist`, чтобы Docker web image не получил отсутствующие файлы. **После** web release и проверки `node scripts/qa/verify-gafus-app-links-live.mjs` все четыре endpoint (apex/www × AASA/assetlinks) должны строго отдавать `200 application/json`, тело источника и ноль redirect. Если хоть один HTML / 404 / redirect — не объявлять App Links готовыми.
3. Собрать **новые** Android AAB и iOS IPA версии 1.7.3, а не использовать старые ноябрьские артефакты. Android: после сборки `node apps/mobile/scripts/verify-android-aab-app-links.mjs <new.aab>`, `node scripts/qa/verify-gafus-app-links.mjs --aab <new.aab>`; должны быть все ожидаемые native manifest пути, оба домена, релизный сертификат. Запустить также 16-KiB ELF и compressor checks.
4. iPhone: проверить, что **фактически подписанный новый IPA** содержит `com.apple.developer.associated-domains` для обоих доменов и team `PJQ8PP666S`, а не только Expo JSON; проверить физическое устройство/перезапуск/после установки новой версии. Универсальные ссылки могут кэшироваться Apple CDN и зависеть от предпочтений пользователя, поэтому тестировать ссылку из Сообщений/Заметок и при холодном/тёплом запуске, не только вставляя её в адресную строку Safari.
5. Android: на реальном устройстве после установки **store APK** запустить `adb shell pm get-app-links ru.gafus.app`, проверить verified состояния gafus.ru/www.gafus.ru. Тапнуть `https://gafus.ru/feed/<id>`, `.../questions/<id>`, `.../reset-password?token=<test>` из внешнего приложения. Проверить отсутствие/наличие login и возвращение к контенту после входа. Для закрытого чата убедиться, что `readGate` запрещает доступ чужому участнику.
6. Не ставить принудительный Store update и Chat2 proxy-only cutover до публикации новых iOS+Android сборок и выполнения предыдущих проверок. Прежние приложения могут не иметь новых native intent filters; OTA их не добавит.
