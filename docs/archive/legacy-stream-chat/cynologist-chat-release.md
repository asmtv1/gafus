## Stream

`node scripts/configure-cynologist-chat-stream.mjs` проверяет конфигурацию. `--apply` создаёт/обновляет выделенную role/type, без затрагивания прочих типов канала. Процесс должен получать server env штатным безопасным способом.

- Authentication и permissions checks включены.
- `gafus_chat_reader`: никаких app grants и никаких user-level channel grants.
- `gafus_cynologist.channel_member`: read-channel, read-channel-members, send-event.
- read/connect/typing events включены, встроенные push выключены.
- create/update/delete messages, upload-attachment, create channel и member mutations клиентам не разрешены.
- Секрет применяется только серверным SDK. Before Message Send не используется как барьер доступа.

Development конфигурация настроена в существующем gafus-chat-dev. Она не является production-конфигурацией.

Production webhook направить на `https://api.gafus.ru/api/v1/stream-chat/webhook`, события message.new и message.read. Проверять подпись исходного тела. ## Отключение

При проблеме выключить флаг на web/API/worker. Новые старты, send и upload закроются, session/history останутся. Таблицы, анкеты, сообщения и миграции не удалять. Вкладка назначенного кинолога сохраняет доступ к существующим диалогам.

Повтор обработки события не создаёт новый StepNotification, push job имеет постоянный ID. Успешная обработка worker/провайдера не доказывает доставку на устройство. Как и существующая push-система, сбой процесса между фактической доставкой и её фиксацией может привести к повторной доставке; строгий exactly-once на устройстве не обещается.

## Общий чат и две вкладки

В пункте меню «Чат» на web и mobile размещены вкладки «Чат с кинологом» и «Общий чат». Для тренера первая вкладка показывает его личные диалоги. Общий чат доступен каждому существующему зарегистрированному аккаунту без подписки и анкеты; имена участников берутся из username. Личные каналы, анкеты, права подписки и напоминания не смешиваются с общей комнатой.

Новый API: `/api/v1/community-chat`, тот же контракт session/messages/attachments. Комната Stream: `gafus_community:general`; клиентские токены разрешают чтение общей комнаты без добавления всех пользователей в members, отправка и загрузки разрешены только серверу. Отдельные таблицы CommunityChatSendOperation и CommunityChatAttachment исключают перенос приватных вложений. Лимиты: текст 5000 символов, 5 вложений, прежние ограничения фото/видео, 20 отправок и 5 загрузок в минуту на аккаунт. Общий чат не создаёт массовых push или напоминаний кинологу. Неиспользованные загрузки удаляются существующим worker через 24 часа.

Перед production запуском применить миграцию `20261001200000_community_chat`, выполнить конфигурацию **production** Stream `node scripts/configure-cynologist-chat-stream.mjs --community --apply` с соответствующими серверными credentials, развернуть web/API/worker и установить `COMMUNITY_CHAT_ENABLED=true`. По умолчанию флаг выключен. В этой работе миграция и конфигурация применены только к локальной тестовой БД и development Stream. В Expo Go сохранён переход к web-чату; официальный нативный SDK требует development build.

Проверка development Stream: `scripts/check-community-chat-live.mjs` с локальной БД, имя которой содержит `_test_`. Восемь проверок: два аккаунта без подписки подключаются и читают общую комнату, серверное сообщение видно другому пользователю, повтор не создаёт дубль, клиент не может отправить напрямую, изменённый повтор/приватное вложение/несуществующий аккаунт отклоняются. Скрипт удаляет только созданные им сообщения и локальные аккаунты, не удаляет общую комнату.

## Модерация общего чата

Права модератора определяются сервером по существующему аккаунту `username=admin`, `role=ADMIN`. Production аккаунт проверен чтением БД; роль менять не требуется. В web и mobile у него появляется раздел «Модерация общего чата»: просмотр сообщений с загрузкой предыдущих, удаление сообщения, бан автора, список банов и снятие бана. Каждое действие требует подтверждения в интерфейсе.

GET `/api/v1/community-chat/moderation` возвращает сообщения и баны только модератору; POST принимает `delete/messageId`, `ban/userId` или `unban/userId`. Удаление мягкое, сервер проверяет CID сообщения: удалить личный диалог через этот API невозможно. Бан Stream ограничен каналом `gafus_community:general`, без таймера, и не распространяется на личный чат. Перед каждой отправкой и загрузкой сервер проверяет активный бан; привилегированный серверный токен не позволяет его обойти. Прямые клиентские записи по-прежнему запрещены, расширять Stream grants не требуется. Правила отображаются в карточке на обеих платформах.

Development проверка расширена до 15 сценариев, включая отказ обычному аккаунту в модерации, бан и запрет server-send/upload, список банов, снятие бана и мягкое удаление. Изменения не развернуты на production.
