# План рефакторинга архитектуры GAFUS

Основание — аудит от 18 ноября 2026 года. Локальная ветка `main`, коммит `04052d616`, плюс находившиеся в работе изменения OTA и оплаты. При аудите граф из 70 проектов не содержал циклов между пакетами, 172 целевых теста прошли. Общая проверка архитектуры остановилась на двух новых OTA-модулях. Это исходная точка для сравнения. Этапы ниже предстоит выполнить.

| Очерёдность | Результат этапа | Зависимость |
|---|---|---|
| 0 | Зафиксирована версия кода и воспроизводятся исходные результаты | До правок |
| 1 | Core больше не может вернуть удалённые зависимости незаметно для CI | После 0 |

## 3. Сохранять шаг, день и статус курса одной операцией

1. Зафиксировать два сценария сбоя в HTTP-тестах. Сейчас при ошибке пересчёта курса практика отвечает успехом, а теория возвращает 500 после записи шага. Для обеих операций возвращать успех только после сохранения всех трёх статусов. При ошибке до фиксации транзакции откатывается вся запись.
2. В `course-progress-server` собрать операцию из существующих `applyStepAndDayTx` и `syncUserCourseStatusFromDaysTx`. Онлайн-вызов открывает одну транзакцию. Офлайн-журнал передаёт свою транзакцию и записывает в ней результат обработки события. Сохранить проверки владельца, курса, привязки шага и правила повторного запроса.
3. Подключить операцию к старту, паузе, возобновлению, сбросу, завершению практики и теории. Убрать повторный пересчёт из HTTP-обработчиков. Сохранить формат успешного ответа для выпущенных клиентов, поддержку запросов с привязкой и без неё. Намерение отправить уведомление записывать по действующим правилам, а обращение к очереди выполнять после фиксации транзакции.
4. На настоящем PostgreSQL прервать операцию между записью шага и пересчётом курса. Отдельно потерять HTTP-ответ после успешной фиксации. Повторить завершение с двух клиентов и одновременно завершить разные шаги одного курса. Проверить записи шага, дня, курса, отметки завершения и количество уведомлений. Повтор в офлайне должен вернуть результат из журнала.

**Готово, когда** при первом сбое все три статуса откатываются, при потере ответа все три сохранены, повтор и гонка дают корректный итог.
