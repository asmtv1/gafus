# iOS 1.7.5 (App Store build 101): обязательный подписанный OTA revision 5

## Две независимые политики

1. `MOBILE_IOS_MIN_VERSION=1.7.5` в GitHub Environment `production`, сериализуется в `ci-cd/docker/.env` при **каждом** деплое API. Это **нативный** барьер: версии iOS ниже 1.7.5 должны перейти в App Store. Android не меняется.
2. `MobileOtaPublication.required=true` для уже опубликованной `ALL` revision 5 (`runtimeVersion=1.7.5`). Это **OTA**-барьер только для установок с подтверждёнными нативными build 101 / fingerprint / подписанным манифестом. Отдельное серверное `/mandatory-policy` использует ту же точную выборку ревизии, что и манифест, а не заставляет обновлять другие несовместимые native runtimes.

## Защита публичной ЮKassa

Ранее система запрещала mandatory, если публичный OTA содержал внутреннюю оплату. Исключение допускается только для `ios/1.7.5`, при включённом явном production-разрешении ЮKassa и наличии проверенной совместимой ревизии отката с отключённой оплатой на **тот же набор** подтверждённых нативных установок. Для iOS 1.7.5 revision 5 проверяется recovery revision 6 (`READY`, `recoveryFor=5`, без ЮKassa).

Значения `MOBILE_OTA_IOS_YOOKASSA_*` должны оставаться истинными. Все операции обязательности пишутся через администраторский API с версионным токеном, UUID операции и повторной проверкой внутри транзакции; не редактировать БД напрямую.

## После выпуска

Проверить production API health 200, переменную `MOBILE_IOS_MIN_VERSION=1.7.5` в работающем контейнере, `required=true`, `revision=5`, `public=true`, `action=ALL` в последней записи `MobileOtaPublication`, `required:true` из авторизованного `/mandatory-policy` для совместимой установки, и действительную подпись публичного Hermes-манифеста revision 5. Старые Store-приложения должны выводить запрос обновления приложения, а не неработающий OTA-экран.
