## A. Chat2 proxy-only: локальная полнота и новая точечная реализация

Уже подтверждённый ранее реальный E2E `node ci-cd/scripts/local-chat2-queue.realpg.mjs --realtime-ws` — **6/6 exit 0**, проверяет настоящий смонтированный `app.ts` Hono endpoint, broker header, live `readGate`, PostgreSQL/Redis/Centrifugo, BAN→unsubscribe, old JWT replay blocked distinct subscription key, proxy outage fail-closed. **В этом проходе он не перезапускался**, поскольку endpoint и broker не менялись.

Компоненты интеграции: `apps/api/src/app.ts` монтирует `/internal/chat2/chat2-subscribe` только при `CHAT2_SUBSCRIBE_PROXY_ENABLED=true`; `apps/api/src/modules/chat2/subscribeProxy.ts` требует не менее 32 символов broker-only secret, сравнивает SHA-256 в constant-time, требует JSON, 8 KiB лимит, `no-store`, вызывает актуальный `readGate`; `apps/api/src/modules/chat2/realtime.ts` добавляет `subscriptionMode: "proxy"` только при opt-in, иначе сохраняет прежний ответ `{token,wsUrl}` и старый room JWT endpoint. `infra/chat2/centrifugo.proxy-only.review.json` содержит отдельный subscription-signing key и private subscribe HTTP proxy; этот шаблон не подключён к production compose.

**Новое конкретное исправление этого прохода:** `packages/core-client/src/chat2/realtimeSubscription.ts` теперь (1) отвергает любой неизвестный/некорректный, но присутствующий серверный `subscriptionMode`, вместо молчаливого перехода на JWT; (2) предоставляет `chat2SubscriptionTransportOptions`, который возвращает `{}` для `proxy` и `{token,getToken}` лишь для `token`. Оба реальных клиента — `apps/web-vite/src/features/chats/Chat2Messenger.tsx` и `apps/mobile/src/features/chat2/Chat2RoomScreen.tsx` — используют общую функцию: повторная подписка в proxy-режиме не может получить room JWT, а обе legacy-ветки сохранили refresh. Структура API не менялась. Unit tests `realtimeSubscription.test.ts` расширены с 5 до 9 сценариев, включая реальное создание параметров, reconnect, token refresh и запрет downgrade. Контракт `ci-cd/scripts/chat2-proxy-cutover.contract.test.mjs` теперь проверяет обе клиентские точки вызова общего helper.

Оба UI считают комнату live/online только после `subscribed` (не просто `connected`), при `disconnected` / `unsubscribed` / `error` переходят в fallback; Web и Mobile оставляют авторизованный HTTP polling раз в 12 секунд. Вход пользователя в другой room привязан к `id`/`owner` и очистке socket; отсутствие production-активации проверяет cutover contract. **Ограничение:** старые мобильные версии после безопасного broker cutover потеряют realtime WS до обновления, хотя HTTP polling останется; это явное release-решение, не «бесшовная совместимость».

Внедрение только по отдельному разрешению: (1) выкатить совместимые клиенты при OFF, (2) проверить закрытый broker→API network ingress + telemetry и inject static header, (3) установить **другой** subscription HMAC signing key в namespace `chat2`, проверить `centrifugo checkconfig --strict` с release-secret, (4) поэтапно включить opt-in API и проверить поведение старых Mobile. При сбое переключиться на авторизованный HTTP fallback/отключить realtime; **не** возвращать старый room JWT signing key, иначе повторится BAN replay.
