# GAFUS iOS 1.7.5 — восстановление дизайна Premium из 1.7.2

## Исходник и визуальная идентичность

В коммите `b4492e73e` версия iOS/Android — 1.7.2. Его `apps/mobile/src/features/app-subscription/components/AppSubscriptionPaywall.tsx` дословно совпадает с сохранённым legacy paywall: именно из него заимствованы 222 строки `StyleSheet.create` в `Premium172Appearance.tsx`. SHA-256 тела исходного блока стилей `9089b897d35086bd72a5d1e514c342f06683afa9c6cb9dc5d668a9a4180bb060`, закреплён тестом.

Визуально сохранены: текстурная светло-бежевая подложка, золотой GAFUS PREMIUM, оливковые карточки с тенями и золотой верхней границей, радиовыбор плана, бейджи и выгода, Impact-цена, список преимуществ с зелёными галочками и исключениями, СБП-иконка и большая кнопка, отдельный блок App Store, юридические тексты и управление активной подпиской.

## Сохранённая архитектура платежей

Состав JS-бандла управляется `ios-public-yookassa`/`standard`. Стандартный iOS export содержит только Apple StoreKit; YooKassa UI живёт в изолированном `InternalCardCheckout.tsx` и попадает в подписанный OTA при профиле `ios-public-yookassa`. Не возвращали legacy API-покупок и не меняли нативную конфигурацию. Версия runtime остаётся iOS 1.7.5, Android 1.7.6 не затронут.

В iOS API сервер сейчас намеренно возвращает `promoCode.entryEnabled=false` и `eligible=false`; интерактивный промокод из 1.7.2 поэтому не показывается. Без отдельного изменения серверной политики воспроизводить нефункциональный input недопустимо. Остальное визуальное оформление включая исходные promo-стили сохранено в компоненте.

## QA и ограничения

- TypeScript mobile без ошибок.
- 22 теста React/iOS/Apple покупки и 13 тестов OTA-профиля/нативного fingerprint пройдены.
- Интеграционный тест проверяет три карты (TRY/POPULAR/MAX_SAVINGS), выбор тарифа и отправку правильного `planCode` в `/yookassa/start`.
- Визуальная сверка настоящего UI на iPhone после доставки новой OTA-ревизии — отдельный шаг; статический тест стилей не заменяет физический скриншот.
- Не проводить реальную оплату и не создавать транзакцию без отдельного ручного теста.
