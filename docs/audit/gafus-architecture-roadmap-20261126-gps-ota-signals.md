# Этапы 5, 10, 14 — эксплуатационные сигналы GPS и обязательного OTA

Дата: 2026-11-27. Код и целевые проверки; не акт production acceptance.

## GPS: два независимых наблюдения

- Mobile: после успешного локального сохранения завершённой прогулки с включённым GPS и активной длительностью не менее 120 секунд основной экран, Android-виджет и iOS-виджет вызывают один диагностический helper. Проверка наличия точки ограничена ownerId/walkId + LIMIT 1, с повторной проверкой текущего владельца. Нет точек → GPS_WALK_NO_POINTS; точки есть, но отсутствует достоверная дистанция → GPS_WALK_INSUFFICIENT_FIX; ошибка чтения → GPS_WALK_STORAGE_UNAVAILABLE. Нулевая достоверная дистанция не считается ошибкой. Отсутствующий clientId, выключенный GPS, незавершённая/короткая прогулка и смена владельца исключены. В телеметрию идут только фиксированные errorCode, без координат и идентификаторов прогулки/владельца. Виджет ожидает лишь локальное помещение диагностики в очередь, не HTTP.
- Server: readWalkGpsOperationalMetrics в tracking-server/walksService.ts, импорт из существующего публичного walks. Часовая когорта записей, впервые синхронизированных 10–70 минут назад, gpsEnabled=true, durationSeconds>=120. Новый составной индекс gpsEnabled/createdAt, существующий составной PK точек, UTC timestamp. Gauges gafus_mobile_telemetry_walk_gps_{eligible_1h,no_points_1h,insufficient_fix_1h,available}. Пустая когорта не равна ошибке БД. Нет разбивки платформы: запись сервера её не хранит. Это не доля потери всех маршрутов и не доказательство потери на устройстве: метаданные и точки приезжают отдельно, поздняя синхронизация исправляет метрику, несинхронизированные прогулки не входят в знаменатель.
- Operator: GafusWalkGpsNoPoints — минимум 3 записи и >=10% от указанной когорты в течение 5m. GafusWalkGpsMetricsUnavailable — 10m. Сверять missing cohort с обезличенными мобильными диагностиками GPS_WALK_* по release/build, проверить фоновые задачи и отставание track sync. Не удалять точки и не объявлять восстановление по одному нулевому gauge.

## OTA

- Расширен прежний анонимный wire/DB check constraint тремя фиксированными событиями: SIGNATURE_REJECTED, MANDATORY_ATTEMPT, MANDATORY_INCOMPLETE. Старые пять событий и failureCode остаются совместимыми. Native log codes UpdateHasInvalidSignature и UpdateCodeSigningError (SDK57) проверяются в пределах текущей попытки; при известном updateId сверяется scope. Ошибка сети, неизвестный код, нечитабельные логи или старое событие не считаются отклонением подписи. Непроверенный manifest ID и текст лога не передаются. Ошибка также имеет отдельный фиксированный diagnostic errorCode OTA_SIGNATURE_REJECTED.
- Обязательная попытка отслеживается только для подтверждённого target. Немедленный отказ, зависание 5 минут или следующая проверка того же всё ещё обязательного target после прерванной попытки дают MANDATORY_INCOMPLETE и OTA_MANDATORY_INCOMPLETE. Локальный marker привязан к platform/runtime/target, сбрасывается после авторитетного решения об отсутствии блокировки, другая ревизия не считается прежним провалом. Один timeout/catch не дублирует сигнал внутри попытки. Диагностика не переключает OTA policy, не добавляет polling, не разблокирует экран и не вызывает дополнительный reload. При завершении процесса до помещения события в очередь доставка best-effort; устройства без новой JS-версии не генерируют новые события.
- Local queue и transport теперь сериализуются независимо; DOWNLOADED queue-only не ждёт HTTP, ACK удаляет только подтверждённые eventId из актуальной очереди. 400 на новые event names при rollback старого сервера не блокирует остальные записи; transient errors сохраняют очередь. Данные и retry остаются ограниченными. Count gauge — события, не уникальные установки и не конверсия установки. MANDATORY_ATTEMPT — число проверок подтверждённого обязательного target, включая блокировку повторной перезагрузки; MANDATORY_INCOMPLETE включает восстановленные наблюдения предыдущих попыток, поэтому отношение counts разных окон не является точной долей неуспеха.
- Operator: GafusOtaSignatureRejected >0 на платформе 2m; GafusMandatoryOtaIncomplete >=3 за час 5m; уже существующий availability alert сохранён. При signature rejection проверять зарегистрированный native release, сертификат, подпись, manifest/fingerprint; не отключать проверку подписи. При незавершённом mandatory — проверить конкретный release и штатную STOP/RECOVER политику, не принудительно обходить gate. Uptrace fixed-platform panels показывают новые event labels. GPS server cohort расположен в Worker section.
