## Changes

1. `packages/core/src/services/auth/identityReadService.ts`: `sessionIsCurrent` checks the actual current DB role against the role in an access JWT. If an access JWT contains `sid`, it must refer to a live, unrevoked refresh-session row for the same account.
2. `packages/auth/src/jwt.ts` + `apps/api/src/routes/v1/auth.ts`: newly issued Hono access JWTs carry the ID of their refresh session. Individual logout or refresh rotation revokes that access credential immediately on its next API use; legacy access JWTs without `sid` remain valid for their maximum previous 15-minute lifetime until cutover.
3. `packages/core/src/services/adminUser/adminUserService.ts`: changes to role or admin-set password invalidate all refresh sessions and set `sessionsRevokedAt` in the same database transaction as the change.
4. `packages/core/src/services/auth/authService.ts`: account-wide compromise revocation now invalidates both refresh and access JWTs. A recently consumed refresh token is classified as a concurrent rotation rather than indiscriminately revoking the account. Atomic rotation conflicts use `RefreshRotationConflictError`.
5. `apps/api/src/routes/v1/auth.ts`: Hono refresh conflicts are HTTP 409 with `REFRESH_CONFLICT`, not 500 or account-wide revoke. Native logout cannot return successful revocation when its DB operation fails (503 with `LOGOUT_REVOKE_FAILED`).
6. `apps/web-vite/src/shared/auth/authApi.ts`: when another browser tab wins cookie rotation, Web retries `/auth/me` once using the current cookie rather than wrongly treating the user as signed out.
7. `apps/mobile/src/shared/lib/api/auth.ts`, `apps/mobile/src/shared/stores/authStore.ts`, and `pendingLogoutRevocations.ts`: Mobile does not claim server logout succeeded after a transport error. Before network I/O it persists a revocation obligation in distinct Expo SecureStore slots (24 bounded records), serialized across concurrent sign-outs. Different offline sessions cannot silently overwrite each other. On the next login/startup, retained credentials are used **only for server revocation**, never authentication; successful revocations are removed. Migrates a previous single-slot record. A full queue is reported and server logout is still attempted; no silent overwrite.

## Explicit bounded queue and runtime note

The protected queue has 24 independent slots. On overflow it fails explicitly, preserves all prior entries and still attempts a direct server logout; device restart/startup/login retries are supported, but no background network daemon is installed. A real device/offline-network lifecycle and Chrome cookie persistence remain unverified; a passing unit test is not proof of those device/browser capabilities. The extra real-SQL test is guarded and skipped unless its explicit isolated-work environment is attested.
