## Проверка настоящего образа Docker с настоящим локальным Hono+MinIO

- Публикация тестовых **фото и видео** создана реальным `createFeedService` в новой локальной PostgreSQL и через настоящую presigned POST загрузку в отдельный локальный MinIO. Исходники не попадали в production.
- **Тот же релизный Docker-образ**, который опубликован в Cloud.ru (`sha256:26fe7a6011930877eb76459e7c6d5a68895387ec027988b7fc40fab4b8da0de0`, `linux/amd64`), запущен локально в ограничениях фото 1 vCPU / 2 GiB, видео 2 vCPU / 8 GiB. Временно созданные в том же контейнере loopback-прокси направляли HTTPS HMAC Core на реальный локальный Hono 3501, а S3 на отдельный MinIO 9500. Использовались исключительно тестовые ключи из игнорируемой директории; никакие production secrets не передавались в Docker.
- Фото → **3 WebP**, 1,503 мс в рабочем Docker-процессе, общий размер 2,686 bytes (простая синтетическая фотография).
- Видео 10s → **2 H.264/AAC MP4 360p/720p + WebP poster**, 9,862 мс в рабочем Docker-процессе, выход 4,696,580 bytes (тестовое видео).
- Реальные HTTP Core callbacks проверены на базе PostgreSQL; оба объекта стали `ready`, оба поста — `published`. `cleanup_source` завершил удаление 2 исходников, финальные 6 медиа-объектов остаются для ручной проверки, дополнительных HLS нет. `FeedStorageJob`: 1 photo, 1 video, 4 cleanup — все `completed`.
- Через Web 5504 проверены login cookie auth (2 HttpOnly cookies, без Secure на точно изолированном HTTP origin), `GET /api/v1/feed/posts?sort=new&pageSize=10` (200, 2 posts). Signed MinIO URLs проверены запросами с `Origin: http://127.0.0.1:5504`: фото 200, видео HTTP 206 Range, корректный CORS. Тестовые S3 credentials не опубликованы.
- Отдельный хостовый Feed poller (`apps/api/src/test/feed-v2-local-link-poller.ts`) **был запущен для первоначальных тестов, но остановлен после уточнения требования Cloud.ru от владельца**: он обращается к настоящему Hono HMAC-API 3501, использует настоящий Sharp/FFmpeg и MinIO 9500, забирая задания только из выделенной локальной базы. Это локальный процесс из исходников, а **не удалённый Cloud.ru Job или новый Docker-образ**. Никакие новые локальные публикации не должны автоматически обрабатываться MinIO после остановки poller; исходная локальная приёмка остаётся историческим доказательством, но не является Cloud.ru end-to-end.

## Ручная проверка

Открыть **http://127.0.0.1:5504/login**, войти тестовым пользователем `feedv2_local` с паролем из приватного файла `.local-pg-scratch/feed-media-local-link-20261028/test-account.private.json` (его не коммитить), затем открыть **http://127.0.0.1:5504/feed**. Доступны два синтетических поста для проверки просмотра фото/видео. Автоматическая обработка новых публикаций через MinIO после 28.10.2026 намеренно остановлена: пользователь требует реальную Cloud.ru Jobs + Cloud.ru S3 цепочку. Не использовать этот старый локальный стенд как доказательство удалённого Cloud.ru исполнения. Вся тестовая активность сохраняется только в выделенной пустой локальной БД и отдельном MinIO.
