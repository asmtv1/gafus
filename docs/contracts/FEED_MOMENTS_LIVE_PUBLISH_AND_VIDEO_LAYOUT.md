# Моменты — автоматическое появление постов и компактные видео

29.10.2026, локальный GAFUS Refactor (Web + Mobile). Production не менялся.

## Ошибка автоматического появления опубликованного поста

Раньше owner-only блок MomentPendingPosts опрашивал /api/v1/feed/me/pending-posts раз в 20 секунд, пока есть pending, но после перехода Core pending → published не обновлял запрос ленты /api/v1/feed/posts?sort=.... В результате карточка обработки исчезала, а опубликованный пост оставался невидимым до ручного обновления страницы или следующего четырёхминутного обновления подписанных ссылок.

Исправление: пока есть pending-посты, серверный запрос owner-only статуса производится раз в 5 секунд (только в видимой вкладке). После успешного нового ответа Core сравниваются предыдущие и текущие pending ID. Если ранее pending публикация исчезла из pending или была повышена до published, инвалидируются все активные query ключи moments/list/ownerId и moments/drafts/ownerId. Сама лента заново запрашивает серверный Feed DTO; никакого оптимистического объявления ready, фальшивого добавления поста или записи в production нет.

Ошибки сети/503, старый cache, неподтверждённые переходы и чужой owner не используются для объявления публикации. Hidden tab опрос не выполняет; при возврате запросы повторяются.

## Компактный предпросмотр роликов

Ориентир — компактная карточка ролика в соцсетях, с сохранением пропорций и штатной возможностью полноэкранного воспроизведения по желанию.

- Web: .feed-v2-video-shell имеет ориентацию portrait/square/landscape из server MP4 metadata и max-height min(440px,52svh) (на узком экране min(440px,54svh)). Portrait изображение вписывается в 4:5 stage, square — 1:1, landscape — 16:9. MP4 object-fit:contain, не обрезает лица/надписи и сохраняет native fullscreen control. preload=none; единственный активный видеоплеер и CDN failover остаются как прежде.
- Mobile: FeedV2Video использует компактную высоту stage, вычисляемую из размеров экрана и исходных metadata; не более 52% высоты окна или 440 dp. Проигрывание остаётся с contentFit=contain и native controls; исходный MP4/обработка/авторизация не менялись.
- Изображения, карусели, ссылки, реакции и комментарии не затронуты.

## 29.10.2026 — проверка паритета Mobile с Web

### Ошибка, обнаруженная в Mobile

Native FeedPublicationQueue опрашивал owner-only endpoint pending-posts каждые 5 секунд, но не уведомлял кэш списка публикаций об исчезновении ранее pending-поста. Независимый список FeedScreen (query key feed/posts/owner/sort) обновлялся лишь по собственному циклу раз в 90 секунд. Смена server pending → published не гарантировала появления готовой публикации без ручного обновления.

Теперь FeedPublicationQueue сохраняет только подтверждённые сервером pending ID для текущего владельца и после их исчезновения вызывает invalidateQueries(feed/posts/ownerId). React Query перезапрашивает активные сортировки, но только Core решает, видна ли публикация. Ошибка 503, refetch in-flight, отсутствие авторизации и смена owner не создают ложного перехода. Локальная мобильная очередь ранее уже вызывала обновление feed при phase=published; этот путь не меняется.

### Видеоплеер в Mobile

- Перед исправлением карточка FeedPostCard показывала poster и принудительно открывала отдельный FeedMediaViewer по нажатию на любую область видео. Существующий компонент FeedV2Video поддерживал inline MP4, но не использовался самой лентой; FeedVideo также выставлял фиктивные размеры 1280x720.
- Карточка ленты теперь передаёт реальные metadata width/height в FeedVideo и показывает native progressive MP4 прямо внутри карточки. Нажатие Play не выполняет переход на отдельную страницу и не запускает fullscreen принудительно.
- Высота карточки видео использует feedV2PreviewHeight для 4:5 портрета, квадрата или 16:9 горизонтального видео, максимум 52% высоты экрана или 440 dp. Изображение/постер/видео используют contain без обрезки и учитывают фактическую ширину контейнера после onLayout.
- Плеер не загружает MP4 до нажатия Play. Используется штатный VideoView с nativeControls и включённым fullscreenOptions.enable. Отдельный полноэкранный FeedMediaViewer использует expanded-предпросмотр вместо ограниченного inline stage; загрузка медиа, подписи, реакции, CDN-failover и очередь Feed V2 не менялись.
