# Моменты — отсутствие опроса в черновике не является ошибкой

Статус: 29.10.2026, исправлено только в GAFUS Refactor (локальный Web/API). Production не менялся.

## Причина

На странице редактирования черновика при публикации текста с фото DevTools показывал GET /api/v1/feed/posts/:postId/poll 404. Клиент ошибочно запрашивал обязательный публичный контракт опроса, хотя отсутствие опроса — нормальное состояние черновика. Старый контракт корректно возвращал 404 при отсутствии опроса. Кроме того, Web неправильно трактовал настоящие 404 (чужой, удалённый или недоступный пост) как «опроса нет».

Конкретный пост cmvtmqbmf000vqzuke0j5pje4 в изолированной WORK PostgreSQL уже имел status=published, две фотографии ready и завершённые Jobs. Ошибка 404 не связана с обработкой медиа.

## Исправленный контракт

- GET /api/v1/feed/posts/:postId/draft-poll: только авторизованный владелец доступного поста. При отсутствии опроса возвращает HTTP 200 и data:null; при существовании — действующий DTO опроса. Чтение возможно в состояниях draft, pending, published, failed, чтобы переход публикации не создавал ложный 404.
- Для чужого, удалённого, скрытого или несуществующего поста возвращается 404, без авторизации 401.
- Публичный GET /posts/:postId/poll остаётся прежним: при отсутствии опроса возвращает 404. Старые клиенты не ломаются.
- Web-редактор использует новую необязательную проверку. Неизвестные результаты PUT нельзя считать отсутствием опроса без успешного повторного GET 200/null.
- Уточнение от 29.10.2026: промежуточный Web-экран «Публикация готова» также удалён. После серверного ACK pending или published пользователь сразу попадает на /moments, где уже работает штатный индикатор обработки. Старые прямые ссылки на /moments/drafts/:postId в состоянии pending/published перенаправляются на /moments.

## Проверки и ограничения

- Тесты Core, Feed Server и Web проверяют отсутствующий/сохранённый опрос, строгие права, отсутствие ложных 404 во время смены состояния, безопасные повторы после неизвестного PUT, переход опубликованного поста в режим просмотра.
- На реальной изолированной WORK PostgreSQL read-only вызов нового Core метода вернул null, публичный Core метод сохранил 404, неавторизованный доступ отклонён.
- Пересобраны пакеты types/core/feed-server; локальный Hono перезапущен на 127.0.0.1:3001 с прежними изолированными PostgreSQL, Redis и MinIO, health вернул 200.
- Chromium Playwright MCP недоступен: ошибка 429; визуальное подтверждение требует проверки обновлённой страницы с очищенной старой консолью.
- Не менялись GAFUS Main, production DB, S3/CDN, Container Jobs и production deploy. Миграция для этого изменения не нужна.
