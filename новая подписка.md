# Monthly App Subscription Plan

**Summary**

- Add a second app subscription plan: monthly, 1100 RUB, 30 days.
- Keep weekly as the existing plan, but make both weekly and monthly configurable and enable/disable-able from the existing `admin-panel` “Настройки подписки” card.
- Show the same set of enabled plans on web and mobile; disabled plans are not shown and cannot be started through API.
- Add separate Apple Product IDs for weekly and monthly iOS subscriptions.

**Key Changes**

- Database:
  - Add a Prisma enum `AppSubscriptionPlanCode` with `WEEKLY` and `MONTHLY`; use it for `planCode` instead of free-form strings.
  - Add `planCode` to `AppSubscription` and `AppSubscriptionPayment`: `"WEEKLY"` or `"MONTHLY"`.
  - Extend `AppSubscriptionSettings` with weekly/monthly enabled flags, prices, interval days, and Apple product IDs.
  - Backfill existing settings/subscriptions/payments as `WEEKLY`.
  - Default weekly enabled, monthly enabled, monthly YooKassa price `1100`, monthly interval `30`.
- Core API/types:
  - Add shared plan helpers in core so offer building, payment starts, Apple validation, and renewal worker all use the same ordered tariff definitions.
  - Change `AppSubscriptionOfferDto` from a single offer to `plans: AppSubscriptionPlanOfferDto[]`.
  - Each plan includes `code`, label/title, `intervalDays`, `currency`, `yookassaPriceRub`, `enabled`, `appleProductId`.
  - Keep shared YooKassa trial fields at offer level because trial is per user/card, not per plan.
  - Change `startYookassaAppSubscriptionPayment` to require `planCode`; reject missing/disabled/unknown plans.
- Payments:
  - Web and mobile send `{ planCode }` to `/api/v1/app-subscription/yookassa/start`.
  - YooKassa initial payments/payment-method setup store the selected plan on subscription/payment metadata.
  - Webhook activation uses the local payment’s stored `periodStart`/`periodEnd` and `planCode`, not current global interval; this avoids wrong durations if admin settings change after checkout starts.
  - Renewal worker renews by `subscription.planCode`, using that plan’s current price/interval even when the plan is disabled; disabling a plan blocks new purchases but does not cancel existing subscriptions.
  - Payment method trial setup also writes `planCode` to the pending subscription and YooKassa metadata so the first post-trial charge uses the selected tariff.
- Admin UI:
  - Replace single-price settings card with two tariff rows: weekly and monthly.
  - Each row has enabled toggle, YooKassa price, Apple Product ID.
  - Admin-only save keeps current role behavior: moderators can view, only admins edit.
- Web/mobile UI:
  - Render enabled plans as selectable tariff cards/rows with identical plan ordering and copy: weekly first, monthly second.
  - Default selected plan: monthly when enabled, otherwise first enabled plan.
  - If only one plan is enabled, show only that plan.
  - If no plans are enabled, show “Подписка сейчас недоступна” and disable payment CTA.
  - iOS uses the selected plan’s Apple Product ID for App Store purchase; YooKassa card payment uses the same selected `planCode`.

**Test Plan**

- Core unit tests:
  - `getAppSubscriptionOffer` returns weekly and monthly enabled plans, filters disabled plans, includes monthly `1100` and separate Apple Product IDs.
  - `startYookassaAppSubscriptionPayment` rejects disabled/unknown plans and creates pending/payment records with the selected `planCode`.
  - YooKassa webhook uses stored payment period/plan instead of recalculating from default settings.
- Worker tests:
  - Weekly subscriptions renew for 7 days with weekly price.
  - Monthly subscriptions renew for 30 days with monthly price.
  - Disabled monthly plan still allows existing monthly renewals.
- Route tests:
  - Web and API `/yookassa/start` pass `planCode` through to core.
  - Invalid or missing `planCode` returns a 400 payment error.
- Admin-panel tests:
  - Settings action validates both tariffs, enabled flags, and Apple IDs.
  - Settings card save payload includes both weekly and monthly config.
- Mobile/web tests:
  - Offer DTO type and paywall presentation handle multiple plans.
  - Selecting monthly sends `MONTHLY`; selecting weekly sends `WEEKLY`.
  - Disabled weekly is absent from both web and mobile paywalls.
- Verification commands:
  - `pnpm --filter @gafus/core test`

  - `pnpm --filter @gafus/web test`
  - `pnpm --filter @gafus/mobile test`

**Assumptions**

- “Панель тренера” means the existing admin-panel settings location, confirmed as `admin-panel`.
- Monthly YooKassa plan uses the same 3-day trial behavior as weekly.
- Monthly duration is 30 days.
- Initial state after migration: weekly enabled, monthly enabled.
- Apple monthly Product ID will be configured by an admin after deployment; until filled, iOS App Store purchase for monthly is unavailable, but YooKassa can still work where enabled.
- Because the start API rejects missing `planCode`, web and mobile clients must be deployed with the API change.
