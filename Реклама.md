# Rewarded Ads Credits Implementation Plan

## Summary
- Реализуем единую механику rewarded credits для web и mobile: `1 реклама = 5 кредитов`, максимум на балансе `5`.
- Расход: любая статья `1`, открытие шага в дне `1`, бронирование консультации `5`.
- Вся бизнес-логика живет в `@gafus/core`; web/mobile/admin остаются тонкими клиентами.
- Реклама: mobile через **Yandex Mobile Ads React Native + Yandex Mediation**, web через **Yandex Rewarded units for websites**. Оба провайдера дают opt-in rewarded flow; у Яндекса mobile mediation выбирает сети через ML, а web rewarded требует явного согласия пользователя. Источники: [Yandex Mobile Mediation](https://ads.yandex.com/helpcenter/en/dev/react-native/quick-start-mm), [Yandex Web Rewarded](https://yandex.ru/support/partner/en/web/units/types/rewarded), дополнительная сверка web-подхода: [Google Ad Manager Rewarded Web](https://support.google.com/admanager/answer/9116812?hl=en).

## Step-By-Step Implementation

1. **Подготовить ветку и зафиксировать контракт**
   - Skills: `superpowers:using-git-worktrees`, `superpowers:test-driven-development`.
   - Создать рабочую ветку.
   - Добавить короткий design/plan doc в `docs/superpowers/plans/`.
   - Зафиксировать продуктовые константы: `CREDITS_PER_REWARD = 5`, `MAX_CREDIT_BALANCE = 5`, `CONSULTATION_BOOKING_COST = 5`, `ARTICLE_OPEN_COST = 1`, `STEP_OPEN_COST = 1`.

2. **Добавить Prisma-модели и миграцию**
   - Skills: `prisma-cli`, `prisma-client-api`, `superpowers:test-driven-development`.
   - Создать модели:
     - `RewardedAdSettings`: platform flags, `paywallCtaEnabled`, `dailyAdLimit`.
     - `RewardedCreditWallet`: `userId`, `balance`.
     - `RewardedCreditTransaction`: ledger `EARN | SPEND | REFUND`, `targetType`, `targetId`, `amount`.
     - `RewardedAdEvent`: rewarded SDK/web events and daily limit audit.
   - Добавить уникальность для spend по `userId + targetType + targetId + type`, чтобы повторное открытие статьи/шага не списывало повторно.
   - Seed/default: settings row disabled, `dailyAdLimit = 1`.

3. **Создать core-сервис rewarded credits**
   - Skills: `superpowers:test-driven-development`, `prisma-client-api`.
   - Создать `packages/core/src/services/rewardedCredits/`.
   - Публичные методы:
     ```ts
     getRewardedCreditsStatus(userId, platform)
     grantRewardedCredits({ userId, platform, provider, placementId, requestId })
     spendRewardedCredits({ userId, targetType, targetId, amount })
     refundRewardedCredits({ userId, targetType, targetId, amount, reason })
     requirePremiumOrRewardedCredits({ userId, targetType, targetId, amount })
     ```
   - Все изменения баланса делать транзакционно.
   - Earn не должен поднимать баланс выше `5`.
   - Grant должен проверять platform flag, `paywallCtaEnabled`, дневной лимит `1/2/3`.

4. **Расширить subscription/access слой в core**
   - Skills: `superpowers:test-driven-development`.
   - Не ломать `getAppSubscriptionAccess`.
   - Добавить отдельный access helper, например `getMonetizedAccessStatus`, который объединяет Premium + rewarded credits.
   - Premium всегда имеет приоритет и не тратит кредиты.
   - Если Premium нет, helper решает, хватает ли кредитов на конкретное действие.

5. **Добавить API routes для rewarded ads**
   - Skills: `hono`, `next-best-practices`, `superpowers:test-driven-development`.
   - В `apps/api` добавить `/api/v1/rewarded-ads/status` и `/api/v1/rewarded-ads/grant`.
   - В `apps/web` добавить зеркальные route handlers `/api/v1/rewarded-ads/status` и `/api/v1/rewarded-ads/grant`.
   - Контракт:
     ```ts
     status: { balance, maxBalance: 5, creditsPerReward: 5, dailyAdLimit, adsWatchedToday, canWatchAd, platformEnabled, paywallCtaEnabled }
     grant: { balance, grantedCredits, canWatchAd }
     ```
   - Клиент не передает amount; сервер всегда начисляет `5`.

6. **Встроить списание в открытие статей**
   - Skills: `next-best-practices`, `hono`, `superpowers:test-driven-development`.
   - Mobile/API: в endpoint получения статьи списывать `1` кредит при успешной выдаче статьи, если нет Premium.
   - Web: в `apps/web/src/app/api/v1/articles/[slug]/route.ts` заменить жесткий `requireWebAppSubscriptionOrThrow` на core helper Premium-or-credit.
   - `targetType = "ARTICLE"`, `targetId = articleId`.
   - Если кредит уже списан за эту статью, повторный GET не списывает.

7. **Встроить списание в открытие шага**
   - Skills: `next-best-practices`, `hono`, `superpowers:test-driven-development`.
   - Списывать `1` кредит не за весь день, а за первый доступ к конкретному шагу.
   - Сервер должен пометить в ответе доступность/lock state по каждому шагу или отдавать 402 при попытке открыть locked step, в зависимости от текущего UI.
   - `targetType = "STEP"`, `targetId = stepOnDayId` предпочтительно, чтобы один и тот же Step в разных днях считался отдельно.
   - Повторное открытие того же шага не списывает.

8. **Встроить списание в бронирование консультации**
   - Skills: `hono`, `next-best-practices`, `superpowers:test-driven-development`.
   - В `POST /api/v1/consultations/book` для web и mobile перед `bookSlot` проверять Premium-or-5-credits.
   - Для idempotent booking не списывать повторно.
   - Если бронь создана, списать `5` с `targetType = "CONSULTATION_BOOKING"`, `targetId = idempotencyKey` или итоговый `bookingId` с защитой от повторов.
   - При отмене пользователем, отклонении кинологом или техническом rollback после создания брони вернуть `5` кредитов через refund.

9. **Добавить admin настройки**
   - Skills: `next-best-practices`, `vercel-react-best-practices`, `superpowers:test-driven-development`.
   - В admin panel добавить блок Rewarded ads рядом с мобильными фичами/подпиской.
   - Поля:
     - Android enabled;
     - iOS enabled;
     - Web enabled;
     - Paywall CTA enabled;
     - Daily ad limit: segmented/select `1 | 2 | 3`.
   - Удалять ничего не нужно.
   - Только `ADMIN` может менять настройки.

10. **Интегрировать mobile rewarded SDK**
    - Skills: `expo:building-native-ui`, `expo:native-data-fetching`, `vercel-react-native-skills`.
    - Добавить `yandex-mobile-ads`.
    - Вынести thin adapter в `apps/mobile/src/features/rewarded-ads/`.
    - Adapter отвечает только за load/show callbacks; начисление делает сервер через `/rewarded-ads/grant`.
    - Использовать Yandex Mediation placement ids из `app.config.js`/public config.
    - После `onRewarded` вызвать grant, invalidate `rewarded-ads/status` и `app-subscription/status`.

11. **Интегрировать web rewarded unit**
    - Skills: `next-best-practices`, `vercel-react-best-practices`, `browser-use:browser`.
    - Создать web adapter, который загружает Yandex RTB loader один раз и вызывает `Ya.Context.AdvManager.render({ type: "rewarded", onRewarded })`.
    - Использовать отдельные block ids для desktop/touch.
    - После `onRewarded(true)` вызвать `/api/v1/rewarded-ads/grant`.
    - CTA должен явно говорить, что откроется реклама и за полный просмотр будут начислены кредиты.

12. **Обновить paywall на web и mobile**
    - Skills: `expo:building-native-ui`, `next-best-practices`, `vercel-react-best-practices`, `expo:native-data-fetching`.
    - Основная CTA остается подписка.
    - Вторичная CTA:
      - если можно смотреть рекламу: `Посмотрите рекламу и получите 5 открытий статей или шагов`;
      - если лимит исчерпан: `На сегодня бесплатные открытия закончились. Новые бесплатные открытия будут доступны завтра.`;
      - если есть кредиты: `Осталось N открытий`.
    - Для консультации при балансе `1-4`: paywall показывает, что для бронирования нужно `5` кредитов.

13. **Добавить аналитику и мониторинг**
    - Skills: `native-data-fetching`, `expo:native-data-fetching`.
    - События:
      - `rewarded_ad_cta_shown`;
      - `rewarded_ad_started`;
      - `rewarded_ad_rewarded`;
      - `rewarded_credits_granted`;
      - `rewarded_credits_spent`;
      - `rewarded_daily_limit_reached`;
      - `rewarded_to_subscription_started`.
    - В payload добавлять `platform`, `targetType`, `balance`, `dailyLimit`, без персональных данных.

14. **Тестирование**
    - Skills: `superpowers:test-driven-development`, `superpowers:systematic-debugging`.
    - Core unit tests:
      - cap balance at `5`;
      - daily limit `1/2/3`;
      - duplicate article/step spend is idempotent;
      - consultation requires `5`;
      - refund returns credits and does not exceed cap.
    - API tests:
      - status/grant auth, flags, limit, platform behavior;
      - article/step/consultation return `402 SUBSCRIPTION_OR_CREDITS_REQUIRED` when no Premium and no credits.
    - Client tests:
      - paywall CTA hidden by flags;
      - limit exhausted text;
      - successful reward invalidates status.
    - Admin tests:
      - only `1/2/3` accepted;
      - non-admin cannot update.

15. **Release verification**
    - Skills: `superpowers:verification-before-completion`, `codex-security:security-scan`, `browser-use:browser`.
    - Run:
      - `pnpm --filter @gafus/core test`;
      - `pnpm --filter @gafus/api test`;
      - `pnpm --filter @gafus/web test`;
      - `pnpm --filter @gafus/mobile test`;
      - `pnpm typecheck`.
    - Manually verify web paywall in browser.
    - Verify mobile on Android/iOS dev builds with test placement ids.
    - Run focused security review for grant/spend endpoints: auth, replay, daily limit, transaction race, client-forged rewards.

## Public Interfaces
- New API namespace: `/api/v1/rewarded-ads`.
- New public config fields for clients:
  ```ts
  rewardedAdsEnabledAndroid: boolean;
  rewardedAdsEnabledIos: boolean;
  rewardedAdsEnabledWeb: boolean;
  rewardedAdsPaywallCtaEnabled: boolean;
  rewardedAdsDailyLimit: 1 | 2 | 3;
  rewardedAdsCreditsPerReward: 5;
  rewardedAdsMaxCreditBalance: 5;
  ```
- New error code:
  ```ts
  SUBSCRIPTION_OR_CREDITS_REQUIRED
  ```

## Assumptions
- Mobile mediation is implemented through Yandex Mobile Mediation first; extra adapters are configured in Yandex UI and native dependency setup as needed.
- Web uses Yandex rewarded units first; Google Ad Manager remains a future provider behind the same adapter interface.
- Web and mobile ship together, but all entry points remain disabled until admin flags are enabled.
- No existing payment/subscription tables are removed or repurposed.
